## 2026-11-22 소유자 입장과 실행기 연결

- 소유자 계정으로 편집기와 저장본 플레이에 들어갈 수 있다. 팀 암호는 협업을 열 때 설정한다. 메모리 저장소로 첫 동시 접속, 암호 없는 팀원 차단, 기존 암호 보존, 세션 만료를 검사했다.
- 제작 브랜치의 GitHub 실행이 서명된 장비 확인 결과를 스튜디오에 보낸다. 일반 호스팅 실행기는 제작 데이터를 받을 수 없다. 전용 실행기는 해당 공유 버전 하나에만 유효한 자격으로 빌드한다. 동시 업로드와 같은 버전의 중복 실행을 검사했다.
- [PR 검사 #6](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45023980094/job/137212832988)에서 같은 실행기의 독립된 Chrome 두 개가 소유자·팀원 입장과 WebRTC 응답 40/40회를 확인했다. 중앙 RTT는 0.9ms, P95는 1.3ms였다.
- [제작 브랜치 검사 #5](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45023976246/job/137213030105)에서 운영 사이트의 실행기 연결이 HTTP 500으로 실패했다. Worker가 GitHub 서명 키를 조회할 때 리디렉션을 직접 확인하도록 수정했다. 키 서버가 302를 반환하면 503을 응답하고 장비 상태를 기록하지 않는지, 정상 키로 서명을 확인하면 연결되는지 메모리 저장소로 검사했다. `npm test` 통과.
- 2026-11-22 22:19 KST, [제작 브랜치 검사 #7의 실행기 로그](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45026778098/job/137221549567)에서 운영 사이트 v9가 GitHub 실행기의 서명된 장비 보고를 수락했다. 이 실행기에는 지정 Unity와 Android 모듈이 없었고, ADB에 연결된 실제 갤럭시 탭은 0대였다. APK가 생성되지 않았다.
- [PR 검사 #8](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45026782770/job/137221439500)에서 편집·저장·전투 검사와 C# 실행 검사를 통과했다. 같은 실행기의 Chrome 두 개에서 WebRTC 응답은 40/40회, 중앙 RTT는 0.7ms, P95는 0.9ms였다.
- 다음 항목은 전용 Unity Android 실행기에서 공유 버전 APK를 생성하고, 아래 갤럭시 탭 플레이와 같은 네트워크의 실제 기기 간 측정을 기록하는 것이다. 장비나 새 결과가 확인될 때 재개한다.

## 2026-11-22 태블릿 미리보기 소유자 입장

- 22:29 KST Android 미리보기에서 로그인 경로가 세 번 404를 반환했다. 같은 접속의 상태 요청에는 플랫폼이 확인한 이메일이 전달됐지만 사이트별 사용자 ID가 없어 기존 소유자 확인이 실패했다.
- 서버가 등록된 소유자 이메일과 일치하는지 매 요청에서 확인한다. 이미 식별된 계정에는 로그인 버튼을 표시하지 않는다. 소유자는 처음 화면에서 편집기로 들어가고, 다른 계정은 팀 암호가 설정된 경우 팀원으로 입장할 수 있다.
- 격리된 저장소에서 ID 없이 소유자 이메일만 전달되는 경우를 재현한 후 `npm test`를 통과했다. 소유자 세션의 프로젝트 열기, 다른 계정과 익명의 접근 거절, 기존 팀 암호와 저장본 보존을 검사했다. 다음 확인은 배포 후 같은 탭에서 편집기 열기다.
- 운영 사이트 v10 배포와 [PR 검사 #11](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45028555454/job/137226840562)을 확인했다. Chrome에서 미리보기와 같은 인증 정보로 편집기가 바로 열렸고, 다른 계정에는 입장 안내가 표시됐다. 운영 주소에 로그인하지 않고 접속한 별도 브라우저에서는 소유자 링크가 OpenAI 로그인 화면을 열었다.

## 실기기와 실행기가 필요한 검증

- Unity 6000.0.23f1과 Android Build Support가 활성화된 빌드 실행기를 연결한다. [연결 설명](ANDROID_BUILD.md). 공유 버전으로 실제 APK가 생성되면 버전·아티팩트·빌드 결과를 확인한다.
- 갤럭시 탭에서 APK 실행, 터치 공격·이동 발판·프레임과 효과·세이브 복원·기기 FPS/P95를 검수한다. 현재 녹화·실측 로그는 없다.
- 같은 네트워크의 두 실제 기기로 네트워크 검사 탭에서 40개 응답과 지연을 측정한다. 샌드박스에서는 직접 연결 후보가 0개여서 기기 간 왕복 수치를 얻지 못했다. 입력 재생 검사와 별개다. 정식 서버 권위형 PvP 경기 서버는 후속 게임 개발 범위다.

## 자동 재개

브랜치 및 PR의 최신 커밋과 이 기록을 먼저 확인한다. 빌드 실행기·기기 결과가 도착하면 남은 검사를 이어간다. 같은 차단 상태에 재배포나 반복 알림을 하지 않는다. 새 오류가 있으면 회귀 테스트를 추가해 수정한다. 모든 실제 검증을 마친 경우에만 완료와 사이트 주소를 알리고 자동 작업을 중지한다.

## 시작 화면·지형·장면·터치 조작 제작

- UI 디자인에서 시작·캐릭터 선택·로딩 화면을 만들고 연결한다. 각 화면의 문구, 그림, 버튼과 위치를 편집할 수 있다. 기존 프로젝트는 사용자가 화면을 추가할 때 연결한다. 메뉴는 맵마다 새로 만들 수 있다.
- 빈 맵에서 지형을 긋고 지울 수 있다. 그린 발판의 색, 위치, 폭, 이동 경로를 수정할 수 있다. 대사는 줄마다 배경·초상·화자 이름·초상 방향·대화창·다음 문구를 바꾸고 해당 줄부터 미리 본다.
- 버튼 외곽선을 직접 찍거나 프리셋으로 선택한다. 전투 HUD의 조이스틱은 위치·크기·색을 편집할 수 있으며 이동량에 따라 속도가 달라진다. 이미지 파일 선택, 붙여넣기, 끌어놓기와 기존 프로젝트 이미지 선택을 연결했다.
- 격리된 자동 검사에서 기존 저장본 유지, 로딩 중 게임 정지와 자산 준비 후 진행, 지형 충돌·추락 복귀, 아날로그 이동, 장면 이미지 참조, 구형 Unity 클라이언트의 좌우 조작 호환을 확인했다. 다음은 실제 브라우저에서 편집·파일 선택·저장·멀티터치 플레이와 배포를 검증하는 것이다.
- 첫 Chrome 실행에서 선택 목록의 이름에 옵션 텍스트까지 포함돼 ‘작업 맵’을 식별하지 못했다. 입력에 고정 접근성 이름을 연결했다. 게임 소스에도 기기의 텍스트 파일을 가져오고 목록에서 직접 여는 경로를 추가했다. 다음 검사는 같은 편집 흐름을 새 빌드에서 재생한다.
