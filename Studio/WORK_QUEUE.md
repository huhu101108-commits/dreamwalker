2026-11-23에 제작 브랜치의 `574859e`를 검수하고 스튜디오 v21을 배포했다. Node·Worker·SQLite, .NET 8, 두 Chrome 프로세스 검사가 통과했다. 사본과 별도 슬롯으로 기기 파일 선택부터 편집·플레이·저장·재실행을 확인했다. 배포 후 스튜디오 첫 화면에 새 편집 모듈이 연결됐고 작업 GPT 패널이 열렸다. [통합 실행 기록](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45166351737)

빌드 실행기가 보고한 Unity 6000.0.23f1 및 Android 모듈은 미설치였고, 승인된 갤럭시 탭은 0대였다. APK 생성·설치·업데이트와 실기기 조작·성능 검수는 대기 상태다. [기기 확인 결과](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45166351737/job/137665836703)

## 태블릿 제작실 통합 검수

기획·작업 카드부터 웹 및 Unity 내보내기까지의 조작, 구현 범위와 실제 장비가 필요한 검사를 [기능별 검증표](VERIFICATION.md)에 기록했다. 제작 보드의 프로토타입·버티컬 슬라이스와 출시 단계는 선택한 프로젝트에 보관한다. 사본별 기기 파일, 버전, 플레이 슬롯과 성능 기록은 검수용 저장소에 보관한다.

- 프로젝트 및 과거 팀 버전 열기, 구형 플레이 세이브 복구, 동시 저장 충돌, 재시작 후 보상 중복을 검사한다.
- 초안과 저장본을 구분하고 같은 공유 버전의 오프라인 HTML, Unity 팩과 프로젝트를 내보낸다. 입력, 규칙, 대사 및 결과에는 콘텐츠 해시를 사용한다.
- 브라우저와 순수 C# 검사가 통과해도 Unity 플레이 모드, 실제 APK 설치, 갤럭시 탭 장시간 성능과 상용 경쟁전은 방법과 별도의 결과를 기록한다.

작업 브랜치 `feature/tablet-production-studio` · PR #3 · [기존 스튜디오](https://dreamwalker-snowfield-studio.congenialcockatoo.chatgpt.site/)

## Unity 전투 규칙과 온라인 친선전 검수

- 백설 전용 규칙에 적중 횟수, 체력 조건, 재사용 대기, 추가 피해·회복·보호막을 지정할 수 있다. 필드와 친선전은 같은 규칙 데이터를 읽는다. 맵의 적 분류로 처치 의뢰를 만들고 저장 후 보상 중복 지급을 검사했다.
- 두 Chrome에서 소유자가 편집·게시한 규칙으로 대전했다. 상대가 새로고침 후 같은 방에 돌아왔고 키 입력으로 결정된 승패가 양쪽에 표시됐다. 보상 지급, 휘장 등록·취소와 동시 구매 처리도 통과했다.
- Unity에서 쓰는 C# 요청·응답 자료형을 .NET에서 실행해 실제 HTTP로 격리된 게임 서버에 접속했다. 브라우저 상대의 방에 참가하고 토큰으로 재접속한 뒤 KO 결과와 지갑 잔액이 양쪽에서 일치했다. [통합 검사 #46](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45108982946/job/137476734428)
- 운영 친선전 입구에서 서버가 기본 규칙 v0을 반환했고 저장소에 방·좌석·플레이어·게시 규칙·매물 테이블이 생성됐다. 정식 경쟁전 지연, 동시접속 부하, Unity 에디터 Play와 갤럭시 탭 APK는 후속 검수 대상이다. 이번 빌드 러너에서 Unity 6000.0.23f1과 Android 모듈이 감지되지 않았고 연결된 태블릿은 0대였다. [장비 확인 #45](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45108976944/job/137476975900)

## 2026-11-22 소유자 입장과 실행기 연결

- 소유자 계정으로 편집기와 저장본 플레이에 들어갈 수 있다. 팀 암호는 협업을 열 때 설정한다. 메모리 저장소로 첫 동시 접속, 암호 없는 팀원 차단, 기존 암호 보존, 세션 만료를 검사했다.
- 제작 브랜치의 GitHub 실행이 서명된 장비 확인 결과를 스튜디오에 보낸다. 일반 호스팅 실행기는 제작 데이터를 받을 수 없다. 전용 실행기는 해당 공유 버전 하나에만 유효한 자격으로 빌드한다. 동시 업로드와 같은 버전의 중복 실행을 검사했다.
- [PR 검사 #6](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45023980094/job/137212832988)에서 같은 실행기의 독립된 Chrome 두 개가 소유자·팀원 입장과 WebRTC 응답 40/40회를 확인했다. 중앙 RTT는 0.9ms, P95는 1.3ms였다.
- [제작 브랜치 검사 #5](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45023976246/job/137213030105)에서 운영 사이트의 실행기 연결이 HTTP 500으로 실패했다. Worker가 GitHub 서명 키를 조회할 때 리디렉션을 직접 확인하도록 수정했다. 키 서버가 302를 반환하면 503을 응답하고 장비 상태를 기록하지 않는지, 정상 키로 서명을 확인하면 연결되는지 메모리 저장소로 검사했다. `npm test` 통과.
- 2026-11-22 22:19 KST, [제작 브랜치 검사 #7의 실행기 로그](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45026778098/job/137221549567)에서 운영 사이트 v9가 GitHub 실행기의 서명된 장비 보고를 수락했다. 이 실행기에는 지정 Unity와 Android 모듈이 없었고, ADB에 연결된 실제 갤럭시 탭은 0대였다. APK가 생성되지 않았다.

- 운영 사이트 v10 배포와 [PR 검사 #11](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45028555454/job/137226840562)을 확인했다. Chrome에서 미리보기와 같은 인증 정보로 편집기가 바로 열렸고, 다른 계정에는 입장 안내가 표시됐다. 운영 주소에 로그인하지 않고 접속한 별도 브라우저에서는 소유자 링크가 OpenAI 로그인 화면을 열었다.

## 실기기와 실행기가 필요한 검증

- Unity 6000.0.23f1과 Android Build Support가 활성화된 빌드 실행기를 연결한다. [연결 설명](ANDROID_BUILD.md). 공유 버전으로 실제 APK가 생성되면 버전·아티팩트·빌드 결과를 확인한다.
- 갤럭시 탭에서 APK 실행, 터치 공격·이동 발판·프레임과 효과·세이브 복원·기기 FPS/P95를 검수한다. 현재 녹화·실측 로그는 없다.
- 같은 네트워크의 두 실제 기기로 네트워크 검사 탭에서 40개 응답과 지연을 측정한다. 샌드박스에서는 직접 연결 후보가 0개여서 기기 간 왕복 수치를 얻지 못했다. 입력 재생 검사와 별개다. 정식 서버 권위형 PvP 경기 서버는 후속 게임 개발 범위다.

## 자동 재개

브랜치 및 PR의 최신 커밋과 이 기록을 먼저 확인한다. 빌드 실행기·기기 결과가 도착하면 남은 검사를 이어간다. 같은 차단 상태에 재배포나 반복 알림을 하지 않는다. 새 오류가 있으면 회귀 테스트를 추가해 수정한다. 모든 실제 검증을 마친 경우에만 완료와 사이트 주소를 알리고 자동 작업을 중지한다.

## 시작 화면·지형·장면·터치 조작 제작

- UI 디자인에서 시작·캐릭터 선택·로딩 화면을 만들고 연결한다. 각 화면의 문구, 그림, 버튼과 위치를 편집할 수 있다. 기존 프로젝트는 사용자가 화면을 추가할 때 연결한다. 메뉴는 맵마다 새로 만들 수 있다.
- 빈 맵에서 지형을 긋고 지울 수 있다. 그린 발판의 색, 위치, 폭, 이동 경로를 수정할 수 있다. 대사는 줄마다 배경·초상·화자 이름·초상 방향·대화창·다음 문구를 바꾸고 해당 줄부터 미리 본다.
- 버튼 외곽선을 직접 찍거나 프리셋으로 선택한다. 전투 HUD의 조이스틱은 위치·크기·색을 편집할 수 있으며 이동량에 따라 속도가 달라진다. 이미지 파일 선택, 붙여넣기, 끌어놓기와 기존 프로젝트 이미지 선택을 연결했다.
- 격리된 자동 검사에서 기존 저장본 유지, 로딩 중 게임 정지와 자산 준비 후 진행, 지형 충돌·추락 복귀, 아날로그 이동, 장면 이미지 참조, 구형 Unity 클라이언트의 좌우 조작 호환을 확인했다. 다음은 실제 브라우저에서 편집·파일 선택·저장·멀티터치 플레이와 배포를 검증하는 것이다.
- 첫 Chrome 실행에서 선택 목록의 이름에 옵션 텍스트까지 포함돼 ‘작업 맵’을 식별하지 못했다. 입력에 고정 접근성 이름을 연결했다. 게임 소스에도 기기의 텍스트 파일을 가져오고 목록에서 직접 여는 경로를 추가했다. 다음 검사는 같은 편집 흐름을 새 빌드에서 재생한다.
- [PR 검사 #16](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45032146455/job/137237864912)에서 Chrome의 파일 선택창·이미지 붙여넣기·로컬 소스 가져오기, 지형 그리기/지우기, 줄별 대사 미리보기, 직접 그린 메뉴 버튼을 검사했다. 격리 저장 후 플레이 주소를 새로 열어 시작→캐릭터 선택→로딩→대사→전투와 조이스틱 이동 중 점프·손 떼기를 통과했다. 다음은 오프라인 HTML과 이동 중 공격, 운영 배포를 확인한다.

## 태블릿 제작실과 기기 파일 가져오기

- ‘파일 선택’은 형식 필터 없는 시스템 파일 입력을 사용한다. 내장 화면이 요청을 처리하지 않을 때 같은 기기의 브라우저에서 고른 파일을 원래 편집 항목으로 돌려보낸다. 임시 연결은 10분 동안 유효하며 원래 편집 세션만 파일을 읽는다. 이미지, 스프라이트 시트, WAV·OGG·MP3, 게임 소스와 프로젝트 백업을 지원한다.
- 제작 보드에 마일스톤·목표·담당자·완료 기준·작업 단계를 기록하고 대상 씬·캐릭터·대사·UI로 이동한다. 에셋 보관함에서 사진과 소리를 프로젝트에 연결하고, 시트 격자·프레임 범위·지속 시간을 설정해 모션을 만든다.
- 맵에서 충돌 지형과 배경 장식 타일을 따로 칠하거나 지울 수 있다. 연속된 타일을 한 행으로 저장한다. 계층 검색, 다중 선택·정렬·잠금, 격자·확대·손 도구, 프리팹 배치·원본 반영·개별 수정 보존을 추가했다.
- 검수·빌드는 씬마다 180틱 시뮬레이션과 화면 검사를 실행한다. 실제 테스트 플레이 후 관찰 결과를 기록하고, 실패를 버그 카드로 연결한다. 게임 내용 지문으로 결과 재사용 여부를 표시한다. 팀 검토·버전 저장·오프라인 게임·Unity 팩과 Android 빌드 경로를 연결했다.
- 격리 저장소에서 일회성 파일 전송과 읽기 권한·만료, 파일명과 바이트 복원, 프리팹 속성 유지, 타일 분할·레이어, 시트 픽셀 범위, 검수 기록, 오디오 저장과 빌드 미디어 분리를 통과했다. 운영 프로젝트·저장 슬롯에는 쓰지 않았다. 다음은 Chrome 전 과정, PR 검사와 기존 사이트 배포 결과 확인이다.
- [PR 검사 #21](https://github.com/huhu101108-commits/dreamwalker/actions/runs/45069128152/job/137351901554)에서 독립 Chrome 간 파일 선택·편집기로 반환, 2×2 시트 모션, 사운드 배정, 타일 그리기, 프리팹 배치, 작업 카드와 검수 저장, 세로 화면 전환을 통과했다. 기존 조이스틱 동시 조작·오프라인 플레이도 통과했다. 별도 미리보기에서도 카드를 검수 단계로 옮기고 씬 자동 검사의 통과 기록을 확인했다.

## 줄별 화면 편집과 태블릿 파일 선택

- 확인한 출발점은 PR #3의 `16f420f`와 사이트 v12다. 앱 안에서 선택기가 즉시 취소되거나 응답이 없을 때 복구 창을 열고, 각 입력에 운영체제 파일 선택기를 그대로 표시한다. 외부 브라우저에서는 일반 파일 선택 페이지에서 먼저 파일을 고른 뒤 편집기에 표시된 코드를 입력할 수 있다. 코드 입력을 고쳐도 고른 파일은 유지된다.

- 로컬 빌드와 `npm test`에서 이전 프로젝트, 좌표·선택지 범위, JSON·Unity ZIP, 코드 연결과 잘못된 코드·만료·파일 바이트 복원 및 기존 회귀 검사를 통과했다. ## 기기 파일 · 화면별 디자인 · 메뉴 기능 · 제작 GPT

- 출발점은 PR #3의 `68e58b6`, 기존 사이트 v13, 통과한 검사 #35다. 기기 파일은 로그인 없이 여는 `/device`와 편집기의 기기 파일 도구에서 먼저 로컬로 연다. 이미지·소리·영상 미리보기, UTF-8 텍스트 편집, 사본 저장, 파일 쓰기 권한을 받은 브라우저에서 원본 저장 및 외부 변경 감지를 지원한다. 프로젝트 초안에는 ‘프로젝트에 사용’을 눌러 넣는다.

- **번역 · 언어**: 프로젝트 `locales`(기본 언어, 언어 목록 최대 12개, 콘텐츠 ID 키의 번역 표, 기본 문구 바꾸기)와 편집 탭(언어별 표·항목/상태/검색 필터·원문 바뀜 검토·`{…}` 표시와 길이 확인·CSV 내보내기/가져오기·쓰지 않는 번역 정리·언어별 테스트 플레이)을 추가했다. 웹(`localizeWorld`)과 Unity(`StudioLocalization`)가 같은 키를 플레이 사본에 적용하고, 게임 기본 문구(현재 123개)는 한 표(`SYSTEM_TEXT` → `StudioSystemText.cs`)를 함께 쓴다. 버튼 동작 «언어 바꾸기», 기기 언어 선택, 기기별 언어 기억, 선택 목록의 저장 값 유지, `{언어}` 표시를 지원한다. 같은 칸을 고친 경우만 충돌로 보고 나머지는 합친다.
- **클라우드 저장·기기 이전**: 온라인 친선전의 기기 게스트로 게임별 클라우드 슬롯(8개, 64KB)과 버전 번호 확인 저장, 24시간 한 번 쓰는 12자리 기기 이전 코드를 서버에 추가했다(`drizzle/0001_cloud_saves.sql`). 화면 버튼 동작 4가지(클라우드 저장·불러오기·이전 코드 받기·코드로 가져오기)를 웹과 Unity가 같은 경로로 처리하고, 결과 안내는 번역 가능한 기본 문구다. 웹 기기는 한 번 클라우드를 쓰면 1분마다 자동으로 올린다.
- **플레이어 오류 보고**: 버튼 동작 «오류 보고 동의 바꾸기»로 동의한 플레이어의 오류(메시지·호출 기록·버전·맵·기기 종류)와 플레이 수를 서버가 묶어 세고(`drizzle/0002_error_reports.sql`), 검수·빌드에서 편집 팀원이 보고 정리한다. 웹은 공개 플레이 링크에서, Unity는 플레이어 빌드에서 보낸다. 게임 소스를 고친 프로젝트의 격리된 게임 창은 스튜디오 페이지가 정해진 서버 요청만 대신 보내고 기기 값을 대신 기억해, 클라우드 저장·오류 보고·온라인 친선전 버튼이 그 창에서도 동작한다.
- **상점 · 뽑기와 확률 공개**: 프로젝트 `shop`(재화 8가지, 상품 100개, 뽑기 30개)과 편집 탭(등급 확률 합 확인, 플레이어 화면 미리보기, 1만 회 시뮬레이션)을 추가했다. 확률은 0.001% 단위 정수로 저장하고 보상별 확률·천장·천장 포함 평균을 게임의 확률 정보 창과 공개 페이지 `/odds`에 같은 값으로 보여 준다. 웹과 Unity가 같은 뽑기 규칙과 보안 난수를 쓰고, 지갑·천장·구매 수·최근 뽑기를 진행 저장에 둔다. 원화 상품은 Unity 스토어 어댑터(`StudioPurchases.Handler`) 연결 지점과 테스트 구매까지 만들었다.
- **제작 편의**: 검수·빌드의 «출시 점검»이 프로젝트 전체의 오류·경고·참고를 한 목록으로 보여 주고 고칠 곳을 연다(저장 식별자는 한 번에 고정). 대사 편집의 «대본으로 쓰기»가 대본 형식 붙여넣기로 대화를 만들고, 대화를 대본과 음성 녹음 CSV로 내보낸다. 작업 찾기가 아이템·의뢰·상점 항목까지 찾는다.
- **쉽게 찾는 편집기**: 새 기기의 첫 화면 «시작하기»(게임 설정, 13단계 제작 순서, 70가지 기능 지도), 도구마다 도움말(F1), 작업 찾기에서 하려는 일로 기능 찾기. 기능 목록은 한 곳(`STUDIO_GUIDE`)에 있고 브라우저 검사가 모든 기능이 실제 도구에 있는지 확인한다.

- **고친 것**: 기능 지도의 «플레이어 오류 보고»가 검증 현황 표의 같은 이름 줄을 가리키고 있었다. 구역 이름을 끝까지 적어 실제 구역을 가리키게 했다(«출시 점검»도 같은 방식으로).
- **호환**: 프로젝트 형식·팀 버전·플레이 저장은 바뀌지 않았다. 보기 방식은 기기의 브라우저 저장소에만 있다.
- **아직 못 한 것**: 실제 갤럭시 탭에서 터치로 확인하지 않았다. 넣어 두는 범위는 프로그래밍을 모르는 사람이 실제로 써 본 결과로 조정해야 한다(`EASY_HIDDEN`). 도구 이름(«UI 디자인» 등)과 화면 안 문구는 그대로다.

### 아직 남은 상용화 과제와 방법

- **다국어 남은 부분**: 언어별 그림·음성, 오른쪽에서 왼쪽으로 쓰는 언어의 배치는 아직 없다.
- **클라우드 저장 남은 부분**: 소셜 로그인(Google·Apple 계정) 연동과 Unity의 자동 업로드는 아직 없다. 게스트 생성 남용을 막는 요청 제한은 배포 환경(WAF 등)에서 정한다.
- **Unity 연동 남은 부분**: 실제 Unity 웹 빌드·APK로 첫 실행 확인. Unity 플레이에는 서버 기능 전달과 진행 저장이 없다. 한자는 웹 플레이어 글꼴에 없다. 웹 미리보기와 Unity의 조작 차이(코요테 타임·점프 버퍼는 Unity에만 있고 값이 코드에 고정)는 그대로다.
- **결제 패키지**: 넣어 둔 Unity IAP 4.15.1은 2026년 6월 8일부터 지원이 끝난 버전이다(동작은 한다). 원화 결제를 쓰기 전에 IAP 5로 옮기고 `StudioUnityPurchasing.cs`를 새 API(StoreController)에 맞게 다시 써야 한다.
- **결제 남은 부분**: 실제 스토어 결제(Google Play 라이선스 테스터, App Store 샌드박스)는 스토어 계정과 실기기에서 확인해야 한다. 계정 로그인(기기를 잃었을 때 지갑 복구), 환불 알림으로 재화 회수, 정기 결제(월정액·패스)는 아직 없다. 의뢰 완료는 기기가 알리므로 서버는 의뢰마다 한 번 지급까지만 지킨다. 스토어 계정·사업자 정보와 확률형 아이템 표시 기준 검토가 필요하다.
- **분석 남은 부분**: 진행 지표(이탈 지점·클리어율)와 네이티브 크래시(Android ANR·신호)는 아직 모으지 않는다. Unity의 C# 예외와 오류 로그만 보낸다.
- **메뉴 남은 부분**: 진동 설정, 화면 밝기, 키·패드 조작 바꾸기 화면, 공지·우편함(서버 데이터)은 아직 없다. 음성이 끝날 때까지 기다리는 자동 진행이 아니라 글자 수로 기다린다.
- **본격 캐릭터 애니메이션**: Spine·Live2D는 각 런타임 라이선스가 필요하다. 지금은 프레임 애니메이션과 초상 움직임으로 대신한다.
