## 같은 버전으로 재현하기

1. **검수·빌드 → 프로젝트 검수 사본 · 별도 저장 슬롯**에서 팀 버전을 고르고 사본 이름을 입력한다. 복제 페이지의 ‘검수 사본 저장’과 주소의 `qa` 식별자를 확인한다. 기존 백업 JSON도 이 사본의 **버전 · 백업**에서 연다.
2. **제작 보드**에서 목표와 완료 기준을 적고 대상 편집기로 이동한다. **기기에서 파일 열기**로 파일을 미리 보고 원래 대상의 속성에 적용한다. 같은 파일 재선택, 취소, 지원 형식 파일로 재시도, 교체와 실행 취소를 시험한다. 내장 화면에서 파일 창이 열리지 않으면 ‘브라우저에서 내 파일 열기’로 같은 태블릿의 브라우저를 사용해 원래 편집기로 돌려보낸다.
3. 사본을 저장한다. **검수·빌드**에서 맵·지점·대사 줄·화면과 새 슬롯 이름을 고르고 검수 플레이를 실행한다. 게임 창을 닫고 탭을 다시 연다. 같은 슬롯 이어하기와 저장 호환성 검사로 결과를 확인한다. **버전 · 백업 → 편집값 변경 비교**는 게임 내 진행과 독립적으로 제작 파일을 비교한다.
4. **게임 소스 → 출력별 지원 · 누락 파일 검사**에서 다섯 출력을 검사한다. 저장본 오프라인 HTML과 Unity 전체 프로젝트/팩을 같은 버전에서 내보낸다. HTML은 네트워크를 끄고 연다. Unity 팩 안의 `Assets/Resources/DreamwalkerStudio/release.json`에는 `rev`와 `contentDigest`가 있다.

- `node scripts/unity-compile-check.mjs --fetch <캐시>`(Unity 6000.0.23f1): Dreamwalker.Runtime 42개(새 `StudioGameMenus.cs`, `StudioMenuRules.cs`)와 에디터·두 테스트 어셈블리·Android 플레이어 구성을 오류·경고 없이 컴파일했다. 플레이 테스트 `HomeStandbyAndSettingsScreensFollowTheStudio`(홈 도착·대기 화면·설정 화면·뒤로·출격·메뉴에서 홈)를 추가했고 실행은 하지 않았다.
- `test-browser-link.mjs` 전체(샌드박스 Chromium 두 프로세스): 새 흐름 `testGameMenus`(1280×800 터치: 세 화면을 버튼 하나씩으로 만들기, 대기 시간·기기 설정 연결·링크 주소 편집, 홈에서 시작, 설정의 즉시 저장, 대기 화면과 터치로 닫기, 저장 알림 유지, 링크, 출격과 메뉴에서 홈, 게임 종료 후 다시 열어 설정 유지, 닫고 같은 순간 다시 열기)를 포함해 모두 통과했다. 실패는 `testDeviceDesigner` 하나로, 이 Chromium이 사본 파일 이름을 `download`로 저장하는 이전부터의 문제다. 번역 흐름은 기본 문구가 늘어 «남은 적» 줄이 표의 둘째 쪽으로 밀려 «항목 더 보기»를 누르도록 고쳤다.
- 같이 고친 것: 게임 루프 안에서 게임을 닫으면 다음 프레임을 다시 예약하던 문제(«게임 종료»에서 드러남), HUD를 다시 그릴 때 기기 설정 컨트롤이 저장 값으로 돌아가던 문제, 창을 닫고 곧바로 다시 연 게임이 앞 게임의 늦게 온 닫기 이벤트에 정리되어 빈 화면이 되던 문제(GitHub CI의 Google Chrome에서 드러남. 이제 새 게임이 앞 게임을 먼저 끝내고 그 이벤트는 무시한다). 호스트 요청(저장·상점 결과 알림 등)은 이제 화면을 다시 그린 뒤 처리해 알림이 화면 이름에 바로 덮이지 않는다(저장 알림은 브라우저 검사로 확인, 상점 알림은 코드 경로만 같다).
- 확인하지 않은 것: Unity 에디터·Android 기기에서 홈·대기 화면 실행, 음량 적용, `Application.Quit`·`Application.OpenURL`(라이선스·기기 필요), 실제 태블릿 스피커에서의 음량, 갤럭시 탭에서의 대기 화면 터치.
