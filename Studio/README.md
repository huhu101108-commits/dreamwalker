# Dreamwalker Studio

[제작 스튜디오](https://dreamwalker-snowfield-studio.congenialcockatoo.chatgpt.site/) · [저장 버전 플레이](https://dreamwalker-snowfield-studio.congenialcockatoo.chatgpt.site/play)

갤럭시 탭 브라우저에서 장면을 만들고 팀 암호로 공유하는 Dreamwalker 제작 도구다. 소유자는 ChatGPT 계정으로 로그인하면 바로 편집할 수 있다. 팀원이 참여할 때는 **버전 · 백업 → 팀 암호 설정**에서 8자 이상의 암호를 정한다. 팀원은 이 암호로 편집·플레이할 수 있다. 암호를 바꾸면 기존 세션이 만료된다.

## 제작자가 직접 검수하는 경로

**검수·빌드 → 프로젝트 검수 사본 · 별도 저장 슬롯**에서 원하는 팀 버전이나 초안을 복제한다. 사본은 이 브라우저에 보관한다. 편집하고 저장한 다음 같은 링크를 다시 열면 작업을 이어갈 수 있다. 실제 게임 진행과 검수용 슬롯은 각각 저장한다. **기능별 검증 현황과 직접 시험할 방법**에는 도구 위치, 조작, 확인한 환경과 남은 조건을 표시한다.

제작 보드에서 기획서와 작업을 연결하고, 각 편집기에서 화면·조작·맵·대사·캐릭터·규칙을 수정한다. 기기에서 연 파일은 적용 전에 미리 보며, 선택한 대상에 반영한 뒤 같은 편집기로 돌아간다. 웹·Unity 비교용 입력과 결과 파일은 제작자가 선택한 공유 버전과 콘텐츠 해시에 연결한다. [기능별 검증표와 실기기 재현 절차](VERIFICATION.md)

## Unity 전투 규칙과 온라인 친선전

**전투 규칙 · Unity**에서 예를 들어 백설이 세 번째 공격을 적중할 때 보호막 5를 얻도록 설정할 수 있다. 자기 체력 조건과 재사용 대기를 추가할 수 있다. 준비·판정·회복은 60틱 기준이다. **저장 · 게임 반영** 후 Unity 프로젝트를 내보내면 `Assets/Resources/DreamwalkerStudio/release.json`에 맵과 규칙이 들어간다. 기존 프로젝트에는 새 C# 런타임을 먼저 반영한다. 필드의 규칙 횟수, 보호막과 처치 의뢰는 체크포인트에 저장된다.

소유자가 **저장한 전투 규칙 게시**를 누르면 새 친선전 방이 그 버전을 사용한다. 브라우저에서 **친선전 열기**, Unity의 **Dreamwalker Studio → Online friendly match**로 같은 방에 들어간다. 한 사람이 방을 만들고 상대가 8자리 코드를 입력한다. 각 기기의 게스트 자격으로 진행 중인 방에 다시 들어갈 수 있다.

친선전은 이동·기본 공격·점프·회피를 지원한다. 서버가 입력을 받거나 방 상태를 조회할 때 경과한 틱을 계산한다. 클라이언트는 통신이 끝난 뒤 다음 입력을 보낸다. 네트워크 검사에서 제작자가 고른 스킬·자원·재사용 대기를 같은 버전으로 재생하며, 두 좌석의 입력 예측과 서버 승인 후 상태 보정을 대조한다. 상용 경쟁전에는 실시간 다단 충돌·모션 동기화, 실제 단말·회선과 서버 부하 검수가 남아 있다. 거래소 화폐는 대전에서 얻는 게임 내 크레딧이다.

## 패드에서 콘텐츠 제작

1. **캐릭터**에서 새 인물을 추가하거나 기존 캐릭터를 복제한다. 전신과 초상화, 지역·소개, 체력·이동·점프·사거리·공격 배율, 패시브와 1~12개 스킬 슬롯을 편집한다. 각 칸에는 관통 돌진, 단일 연격, 추적 복귀, 영역 공격, 갈고리 접근, 직선 원거리 타격을 연결할 수 있다. 직접 조립한 동작에서는 타격, 접근, 이동, 대기, 회복, 원위치 복귀를 원하는 순서로 조합한다.
2. **대사 편집**에서 화자·대사·선택지를 작성한다. 일반 대사는 다음 줄로 진행하고 선택지는 지정한 줄로 이동하거나 대화를 끝낸다. 대사 순서를 바꿔도 선택지의 연결은 유지된다. **스토리 로드맵**에서는 캐릭터별로 에피소드의 제목과 한 줄 요약, 시작점, 선택지별 도착점, 연결 대화와 배경 맵을 정한다. 기존 대사를 여러 캐릭터가 함께 쓸 수 있다. 카드에서 경로를 읽어 보고 HUD나 메뉴에 **현재 캐릭터 스토리** 버튼을 추가하면 게임에서도 열린다.
3. **맵 편집**에서 배치 도구를 선택한 뒤 캔버스를 눌러 개체를 놓는다. 선택 도구로 옮기거나 좌표를 입력한다. 가로 길이 100~3200(한 화면은 100), 발판 너비, 적별 그림·체력·피해·추격 속도·감지 거리·공격 간격, 배경·소품, 시작 캐릭터, 대화 지점과 출구를 설정한다. 맵 연결 설정에서 입장·출구 대화, 목적지, 적 처치 조건, 화면, 게임 시작 맵을 지정한다.
4. **UI 디자인**에서 HUD, 메뉴, 대화 또는 사용자 화면을 만든다. **＋ 버튼 추가**로 버튼을 놓고 터치로 끌거나 좌표와 크기를 %로 입력한다. 그림·글자·테두리·모서리·누른 색·앞뒤 순서와 상태별 표시/활성 조건을 편집한다. **버튼 동작**과 **후속 동작**으로 상태 변경, 다른 화면 열기, 이전 화면 복귀, 맵 이동, 대화, 교대, 스킬 사용과 이벤트 발송을 순서대로 실행한다.
5. **테스트 플레이**는 선택한 맵과 편집 중인 초안으로 시작한다. **저장 · 게임 반영**은 팀 버전을 만든다. 플레이 링크는 저장된 시작 맵을 연다. 진행 중인 플레이는 시작할 때 받은 버전을 사용한다. PC에서 A/D나 방향키로 이동하고 Space로 점프하며 Z/X/C/V/B로 공격·스킬을 사용한다.
6. **버전 · 백업**에서 최근 30개 저장본을 초안으로 복원하거나 이미지 포함 JSON을 내보낸다. 팀원이 같은 버전을 먼저 저장하면 두 번째 저장은 거절된다. 작업 내용을 백업한 뒤 최신 버전을 열어 변경 사항을 합칠 수 있다.

이름을 고치면 목록(작업 캐릭터·작업 맵 같은 선택 상자), 캐릭터 카드의 이름·지역·소개와 스킬 슬롯 탭이 입력하는 대로 바뀐다. 도구를 다시 그리지 않으므로 입력 중인 칸과 누르고 있는 터치가 끊기지 않는다. 아래쪽 알림은 9초 뒤 사라지고(진행 중을 알리는 «…»로 끝나는 알림은 다음 알림까지 남는다) 누르면 바로 닫힌다.

## 캐릭터 중심 연출 (표정·프로필·필살기)

캐릭터를 중심으로 진행하는 게임에 필요한 연출을 **캐릭터**, **대사 편집**, **UI 디자인**에서 만든다. 모든 항목은 선택 사항이다. 추가하지 않은 프로젝트와 기존 세이브는 이전과 같이 동작한다.

- **표정 세트**: 캐릭터 탭의 **표정 세트**에서 표정 이름을 직접 정해 추가하거나 **표정 이미지 여러 장 가져오기**로 파일 이름을 표정 이름으로 쓴다. 대사 줄마다 **화자 표정**을 고르면 기본 대화창과 줄별 화면의 화자 초상이 그 표정으로 바뀐다. 표정 그림을 바꾸면 그 표정을 쓰는 모든 줄이 함께 바뀌고, 표정을 지우면 해당 줄은 기본 초상으로 돌아간다. 초상화·전신 이미지가 없는 캐릭터는 첫 표정 그림을 기본 얼굴로 쓴다.
- **등장 인물 배치와 화자 강조**: 대사의 **이 줄 화면 편집**에서 **무대에 세울 인물 → 인물 레이어 추가**로 인물을 왼쪽·오른쪽·가운데에 세운다. 레이어마다 인물과 표정을 고를 수 있다. **화자 강조 · 말하지 않는 인물 어둡게**를 켜면 그 줄의 화자가 아닌 인물이 어둡게 보인다. 내레이션 줄에서는 모두 밝게 보인다. **구도 복사 → 다음 대사 → 구도 붙여넣기**로 같은 무대를 이어 쓴다.
- **초상 움직임**: 캐릭터 탭 **초상 움직임**에서 숨쉬기(없음·약하게·보통·강하게)를 고른다. 표정 세트의 선택한 표정마다 **눈 감은 그림 · 깜박임**과 **말하는 그림 · 입 움직임**을 넣을 수 있고, 같은 섹션의 기본 초상 그림은 표정을 고르지 않은 줄에 쓴다. 대사창과 이 줄 화면의 화자 초상·등장 인물 레이어가 4초마다 0.13초 깜박이고, 화자는 대사 글자가 나오는 동안 0.12초 간격으로 입을 움직인다. 섹션의 미리보기에서 바로 확인한다. 그림을 넣지 않으면 그 동작은 일어나지 않으며, 움직임 줄이기를 켠 기기에서는 숨쉬기를 멈춘다.
- **프로필 항목**: 소속·생일·성우처럼 항목 이름을 직접 정한다. UI 디자인의 텍스트·버튼·캐릭터 이름·스킬 게이지 문구에 `{프로필:항목 이름}`을 쓰면 플레이 중인 캐릭터의 값이 표시된다. 프로필과 표정은 캐릭터 세팅 프리셋으로 복사되지 않는다.
- **스킬 게이지**: 캐릭터 탭 오른쪽 **스킬 게이지 · 필살기 자원**을 켜고 최대치·시작값과 적중·피격·처치 1회당 충전량을 정한다. 스킬마다 **게이지 소모량**을 정하면 게이지가 모자랄 때 그 스킬이 나가지 않는다. 게이지는 캐릭터마다 따로 유지되고 진행 저장에 포함된다.
- **스킬 연출**: 스킬의 **스킬 연출 · 컷인 / 외침 / 음성**에서 컷인 그림·띠 색·문구·길이(틱), 외침 대사, 음성을 정한다. **컷인 동안 전투 정지**를 켜면 적·타이머·스킬이 정한 틱만큼 멈춘 뒤 이어진다. 컷인 없이 외침 대사만 쓰면 캐릭터 위에 말풍선이 표시된다. **▶ 연출 미리보기**로 편집 중에 확인한다.
- **HUD**: UI 디자인에서 **스킬 게이지 (필살기 등)**, **보스 체력 바** 요소를 추가한다. 보스 체력 바는 전투 방식이 보스인 적이 시야에 들어오거나 피해를 입으면 나타나고, 체력 단계 기준에 표시선이 있다. 스킬 버튼에서 **스킬 재사용 대기 · 게이지 충전 표시**를 켜면 남은 대기 시간, 게이지 충전 정도와 사용 가능 상태가 버튼에 표시된다.

웹 플레이·오프라인 HTML·Unity 런타임이 같은 데이터를 읽는다. 게이지 증감, 컷인 정지 틱, 표정 선택 순서와 프로필 치환은 `scripts/native-check/character-stage.json`을 웹(`npm test`)과 C#(.NET 계약 검사)이 같은 기대값으로 검사한다. Unity 화면에서는 컷인 띠를 회전한 사각형으로 그리고 말하지 않는 인물을 어둡게만 표시하며, 웹의 채도 낮춤과 이동 곡선은 근사치다.

## 번역과 다국어 (번역 · 언어)

원문(기본 언어)은 각 편집 화면에서 쓰고, **번역 · 언어** 탭에서 언어를 추가해 한 표에서 번역한다. 대사·화자 표시 이름·다음 버튼·선택지·줄 화면 문구, 캐릭터 이름·지역·소개·프로필 값·스킬 이름·컷인 문구·외침, 로드맵 제목·요약·분기, 맵 이름과 적·소품 이름, UI 화면의 글자·입력 안내·입력 오류 문구·선택 목록 항목, 아이템·의뢰 이름, 게임 제목과 게임 기본 문구가 대상이다.

- **번역 키**: 위치가 아니라 콘텐츠 ID로 찾는다(`story/<스토리>/line/<줄>/text`, `screen/<화면>/<요소>/text`, `character/<캐릭터>/name`, `system/<이름>` 등). 줄 순서를 바꾸거나 다른 줄을 고쳐도 번역이 따라간다. 스킬·선택지·분기·선택 항목은 순서 번호를 쓴다.
- **상태**: 각 칸은 번역 필요·원문 바뀜·번역 완료로 표시된다. 번역은 만들 때의 원문 해시를 기억하므로 원문을 고치면 «원문 바뀜»이 되고, 번역을 고치거나 **원문 확인함**을 누르면 다시 완료가 된다. 원문과 `{입력:…}`·`{프로필:…}`·`{변수:…}`·`{언어}` 표시가 다르거나 원래 칸 길이보다 긴 번역은 «확인 필요»로 찾는다. 항목·상태·검색(원문·번역·위치) 필터로 좁힌다.
- **번역가와 주고받기**: **번역 CSV 내보내기**는 `key, where, max, <기본 언어>, <언어…>` 열의 UTF-8 CSV(엑셀용 BOM)를 만든다. 언어 열을 채워 **번역 CSV 가져오기**로 읽으면 바뀐 칸만 반영한다. 빈 칸은 기존 번역을 지우지 않는다. 내보낸 뒤 원문이 바뀐 칸은 «원문 바뀜»으로 들어온다. 지금 게임에 없는 키, 목록에 없는 언어 열, 1200자를 넘는 칸, `{…}` 표시가 다른 칸은 결과에 따로 알린다. `=`·`+`·`-`·`@`로 시작하는 칸은 스프레드시트가 수식으로 읽지 않도록 앞에 `'`를 붙여 쓰고 가져올 때 뗀다.
- **게임 기본 문구**: 글자를 비운 버튼의 동작 이름(점프·베기·메뉴·화면 열기 등), HUD(로딩·남은 적·스킬 게이지·보스), 대화 버튼(다음 대사 →·대화 마치기·내레이션), 장비·의뢰 목록, 결과 화면, 진행 저장 안내, 웹 플레이 막대, 클라우드 저장·오류 보고·상점·확률 정보 안내처럼 게임이 직접 쓰는 문구 114개다. 기본 언어에서도 **게임 기본 문구 바꾸기**로 바꿀 수 있고 다른 문구처럼 번역한다. 웹과 Unity가 같은 표를 쓴다(`Assets/Dreamwalker/Scripts/Demo/StudioSystemText.cs`는 `node scripts/unity-locale.mjs`로 만든다).
- **게임에서**: 처음에는 기기 언어(브라우저 언어 목록, Android 언어 태그나 Unity 시스템 언어)와 맞는 언어로 열고, 없으면 기본 언어로 연다. 중국어는 지역에 따라 간체·번체를 고른다. UI 디자인의 버튼 동작 **언어 바꾸기**는 다음 언어로 넘기거나 지정한 언어로 바꾸며, 고른 언어는 그 기기에 게임별로 기억한다(`dreamwalker-language-v1:<저장 식별자>`). 글자에 `{언어}`를 쓰면 지금 언어 이름이 보인다. 선택 목록 입력은 보이는 항목만 번역하고 저장 값은 원문을 그대로 쓴다. 바꾸면 모든 글자가 그 자리에서 바뀌고, 나오던 대사는 같은 위치부터 새 언어로 이어진다. **이 언어로 테스트 플레이**로 바로 확인한다.
- **빌드와 협업**: 웹·오프라인 HTML·Unity 빌드에는 지금 게임에 있는 항목의 번역만 들어가고 검토용 해시는 빠진다. 지운 콘텐츠의 번역은 **쓰지 않는 번역 정리**로 지운다. 두 사람이 다른 언어나 다른 칸을 번역하면 저장 때 합쳐지고, 같은 칸을 다르게 고치면 충돌로 알린다. 언어는 12개, 번역 항목은 6만 개, 번역 한 칸은 1200자까지다.
- **글꼴과 한계**: Unity는 한국어 OS 글꼴 다음에 일본어·중국어·태국어 글꼴을 대체 글꼴로 찾는다. 오른쪽에서 왼쪽으로 쓰는 언어(아랍어·히브리어)의 화면 배치는 지원하지 않는다. 언어마다 다른 그림·음성은 아직 없다.
- **바뀐 기본 문구**: 웹에서 글자를 비운 버튼이 편집기용 동작 이름(예: «지정 화면 열기») 대신 Unity와 같은 플레이어용 이름(«화면 열기»)을 쓴다. Unity의 대화 다음 버튼은 웹과 같이 «다음 대사 →»·마지막 줄 «대화 마치기», 결과 화면 버튼은 «이 맵 다시 시작», 빈 장비·의뢰 목록은 웹과 같은 문장을 쓴다. 회피 버튼은 Unity에서도 «회피»로 보인다.

## 상점 · 뽑기와 확률 공개

**상점 · 뽑기** 탭에서 재화, 상품, 확률형 뽑기를 만든다. 모두 제작자가 정하는 값이며 기본 상품이나 확률은 없다.

- **재화**: 최대 8가지. 이름, 시작 수량, 최대 보유, 아이콘. 화면 글자에 `{재화:<재화 ID>}`를 쓰면 보유량이 보인다.
- **상품**: 최대 100개. 게임 재화 가격 또는 원화 가격(스토어 상품 ID 필요), 지급 내용(재화·아이템 최대 10가지), 플레이어당 구매 한도. 버튼 동작 **상품 구매**로 판다.
- **뽑기**: 최대 30개. 1회 비용, 연속 뽑기 횟수(2~10, 0은 없음), 천장(N회째 최고 등급 확정, 0은 없음), 등급 최대 6개와 등급별 확률(0.001% 단위, 합이 정확히 100%), 등급마다 보상(아이템·재화·캐릭터)과 가중치. 보상 하나의 확률은 등급 확률을 가중치로 나눈 값이며, 화면과 공개 페이지에 0.001% 단위로 반올림해 같은 값으로 나온다. 천장이 있으면 천장 포함 평균 확률((1-(1-p)^N)/p회마다 한 번)도 함께 공개한다. 버튼 동작 **뽑기 1회**, **연속 뽑기**, **확률 정보 보기**로 쓴다.
- **편집기 도구**: 등급 확률 합을 바로 확인하고, 플레이어가 볼 확률 정보 화면을 미리 보며, **1만 회 뽑아 보기**로 이 기기의 실제 규칙·난수로 공개 확률과 결과, 평균·최장 간격, 천장 발동 횟수를 비교한다. 상점이나 뽑기에 쓰인 아이템·재화는 지울 수 없다.
- **게임에서**: 뽑기는 기기의 보안 난수(웹 `crypto.getRandomValues`, Unity `RandomNumberGenerator`)로 등급을 먼저, 그 등급의 보상을 다음에 정한다. 웹과 Unity의 규칙은 같은 표(`scripts/native-check/gacha.json`)로 검사한다. 결과와 확률 정보는 화면 위 기본 창에 나오고(닫기·Escape·뒤로), 확률 정보에는 천장까지 남은 상태와 최근 뽑기 10개가 보인다. 지갑·천장 횟수·구매 수·최근 뽑기 30개는 진행 저장에 들어가며, 메뉴가 열려 있어도 구매·뽑기 직후 마지막 기기 저장에 바로 반영한다. 상점이 없는 게임의 저장 형식은 그대로다.
- **캐릭터 뽑기**: 보상 종류 **캐릭터**는 한 명(수량 1)을 준다. **캐릭터**에서 **처음엔 잠김 (뽑기·보상으로 얻음)**을 켠 캐릭터는 뽑기·상품으로 얻기 전에는 캐릭터 선택·교대·맵 시작에 나오지 않는다(맵의 시작 캐릭터가 아직 없으면 지금 쓰던 캐릭터로 들어간다). 처음부터 쓸 수 있는 캐릭터가 하나 이상 있어야 하고, 게임 시작 맵의 캐릭터는 잠글 수 없다. 이미 가진 캐릭터가 다시 나오면 그 뽑기의 **대신 줄 보상 정하기**(아이템·재화)를 주고, 정하지 않았으면 아무것도 주지 않는다. 결과 창은 처음 얻은 캐릭터에 «NEW», 이미 가진 캐릭터에 «보유 중 → 대신 받은 보상»을 보인다. 가진 캐릭터는 진행 저장(`owned`)과 서버 지갑에 남는다. 이 값이 없는 이전 저장은 잠기지 않은 캐릭터만 가진 것으로 읽는다. 상점·뽑기에 쓰인 캐릭터는 지울 수 없다.
- **의뢰 보상 재화**: **아이템 · 의뢰**에서 의뢰의 **보상 종류**를 **재화**로 고르면 완료할 때 상점 재화를 준다(한 번에 99999까지). 플레이로 뽑기 재화를 모으게 할 때 쓴다.
- **버튼 바로 놓기**: 뽑기마다 **화면에 뽑기 버튼 놓기**가 홈 화면(없으면 그 맵의 메뉴)의 빈 자리에 1회 뽑기·연속 뽑기·확률 정보 버튼을 함께 놓는다. 그 뽑기의 버튼이 이미 있거나 자리가 없으면 알려 주고 놓지 않는다.
- **원화 결제**: 웹에는 결제가 없다. 스튜디오 테스트 플레이는 실제 결제 없이 테스트 구매로 끝나고, 공개 플레이 링크는 «결제할 수 없어요»를 알린다. Unity 프로젝트에는 Unity IAP 4.15.1(`Packages/manifest.json`)과 어댑터 `Assets/Dreamwalker/Scripts/Purchasing/StudioUnityPurchasing.cs`가 들어 있어, 원화 상품마다 같은 스토어 상품 ID의 소모성 상품을 Google Play·App Store에서 판다(스토어에 같은 ID로 등록한다). 게임이 지급을 저장한 뒤에야 구매를 확정하므로 도중에 끊긴 구매는 다음 실행 때 다시 와서 지급된다. 같은 구매는 한 번만 지급한다(기기 저장의 최근 영수증 100개, 서버 지갑에서는 서버의 영수증 기록). Unity 에디터에서는 IAP의 가짜 스토어로 테스트 구매가 된다. Unity IAP 패키지를 빼고 직접 만든 어댑터를 쓸 때는 이전처럼 `StudioPurchases.Handler`에 연결한다. 서버 지갑을 끈 게임은 재화와 영수증 확인이 기기에만 있어 기기 저장을 고치거나 가짜 영수증을 쓰는 부정 사용을 막지 못한다. 유료 재화를 파는 게임은 아래 «서버 지갑과 결제 확인»을 켠다.
- **확률 공개 페이지**: 스튜디오 사이트의 `/odds`가 저장된 팀 버전의 모든 뽑기 확률·천장·평균을 누구나 볼 수 있게 보여 준다(확률형 아이템 정보 공개용). 상점 이름과 확률 외의 프로젝트 내용은 나가지 않는다.
- **번역**: 재화·상품·뽑기·등급 이름과 안내 문구는 **번역 · 언어**에서 번역한다.

## 서버 지갑과 결제 확인

**상점 · 뽑기 → 서버 지갑**에서 **서버 지갑 사용 (온라인 게임)**을 켜면(`shop.server`) 재화, 천장 횟수, 구매 수, 상점이 준 아이템·캐릭터, 최근 뽑기를 서버가 정하고 보관한다. 유료 재화를 파는 게임은 켠다. 끈 게임은 지금처럼 기기 저장에만 둔다. 재화를 하나 이상 만든 뒤 켤 수 있다.

- **지갑의 주인**: 클라우드 저장과 같은 기기 게스트마다, 게임 저장 식별자마다 하나다(`dw_wallets`). 기기 이전 코드로 게스트를 옮기면 지갑도 함께 간다. 스튜디오 테스트 플레이와 Unity 에디터는 `preview-` 지갑을 따로 쓴다.
- **서버가 하는 일**: 뽑기는 서버의 보안 난수로, 저장한 팀 버전(공개 확률 페이지 `/odds`와 같은 버전)의 확률·천장·중복 보상대로 뽑는다. 재화로 사는 상품, 의뢰 보상 재화(의뢰마다 한 번)도 서버가 지급한다. 게임은 서버가 돌려준 지갑으로 화면을 바꾸고 기기 저장에도 남긴다. 상점을 고치면 없어진 항목은 빠지고 새 재화는 시작 수량에서 시작한다. 같은 지갑에 동시에 온 요청은 버전 번호로 하나씩 반영한다.
- **원화 결제 확인**: Unity IAP가 넘긴 영수증을 서버가 스토어에 확인한 뒤 한 번만 지급하고, 게임은 그다음에 스토어 구매를 확정한다. 지갑 저장과 영수증 기록(`dw_receipts`의 스토어·거래 번호)은 한 묶음으로 기록되어, 같은 영수증이 다시 오면 지급 없이 확정만 한다. Google Play는 서비스 계정으로 `purchases.products.get`을 불러 결제 완료 상태인지, App Store는 App Store Server API(운영 서버, 없으면 샌드박스)로 번들 ID·상품 ID·환불 여부를 확인한다. 스튜디오 테스트 플레이의 테스트 결제는 `preview-` 지갑에서만 받는다.
- **호스팅 비밀 값**: 결제 확인 키는 호스팅의 비밀 환경 변수로만 넣는다. 프로젝트 데이터·팀 버전·게임 내보내기에는 들어가지 않는다. 값이 없는 스토어의 결제는 확인하지 않고 확정도 하지 않는다.
  - `GOOGLE_PLAY_SERVICE_ACCOUNT`: Play Console의 사용자 및 권한에서 이 앱의 주문 정보를 볼 수 있게 초대한 Google Cloud 서비스 계정의 JSON 키 전체
  - `GOOGLE_PLAY_PACKAGE`: Android 패키지 이름
  - `APPLE_ISSUER_ID`, `APPLE_KEY_ID`, `APPLE_PRIVATE_KEY`: App Store Connect의 In-App Purchase 키(발급자 ID, 키 ID, `.p8` 파일 내용 전체)
  - `APPLE_BUNDLE_ID`: iOS 번들 ID
- **배포**: `drizzle/0003_server_wallet.sql`(`dw_wallets`, `dw_receipts`)을 0000~0002와 함께 적용한다. 경로는 `POST /api/arena/wallet`(지갑 읽기), `POST /api/arena/shop`(`buy`·`draw`·`claim`), `POST /api/arena/receipt`(영수증)이며 기기 게스트 세션이 필요하다. 게임 소스를 고쳐 격리된 창에서 실행하는 웹 게임은 스튜디오 페이지가 이 세 요청을 대신 보낸다.
- **연결이 안 될 때**: 서버 지갑 게임은 서버 없이 사거나 뽑지 않고 «서버에 연결하지 못했어요»(`shop.server`)를, 영수증을 확인하지 못하면 «결제를 확인하지 못했어요. 결제가 되었다면 다시 실행하면 지급돼요.»(`shop.verify`)를 알린다. 확정하지 않은 구매는 스토어가 다음 실행 때 다시 보내므로 그때 다시 확인한다. Google Play는 3일 안에 확정하지 않은 구매를 자동으로 환불하므로 출시 전에 비밀 값을 넣는다. 두 문구는 **번역 · 언어**에서 바꾼다.
- **아직 없는 것**: 계정 로그인(Google·Apple 로그인)이 없어서 기기를 잃고 이전 코드도 없으면 지갑을 되찾지 못한다. 의뢰 완료는 기기가 알리므로 서버는 의뢰마다 한 번만 지급하는 것까지만 지킨다. 환불 알림(Google 실시간 개발자 알림, App Store Server Notifications)으로 재화를 회수하지 않는다. 실제 스토어 결제는 이 저장소의 검사가 아니라 스토어의 테스트 계정으로 확인해야 한다.

## 클라우드 저장과 기기 이전

플레이어의 진행을 스튜디오 서버에 맡기고 다른 기기로 옮긴다. 온라인 친선전과 같은 기기 게스트(웹은 `dw_arena` 쿠키, Unity는 `dreamwalker-arena-guest-v1` 토큰)를 쓰므로 회원 가입 화면이 필요 없다. UI 디자인에서 버튼 동작으로 화면에 둔다.

- **클라우드에 진행 저장**(`cloudSave`): 이 기기의 진행 저장을 그대로 올린다. 기기는 마지막으로 본 클라우드 버전 번호를 기억하고, 그사이 다른 기기가 저장했으면 덮어쓰지 않고 «다른 기기에서 더 최근에 저장했어요»를 알린다. 대상 «이 기기 진행으로 덮어쓰기»를 고른 버튼은 그래도 올린다. 한 번 클라우드에 저장한 웹 기기는 이후 진행이 바뀌면 1분에 한 번까지 자동으로 올린다.
- **클라우드에서 진행 불러오기**(`cloudLoad`): 클라우드 사본을 이 기기 저장으로 바꾸고 그 자리에서 연다. 이 버전에서 열 수 없는 기록이면 아무것도 바꾸지 않는다.
- **기기 이전 코드 받기**(`transferIssue`): 12자리 코드(예: `ABCD-EFGH-JKMN`)를 만든다. 24시간 동안 한 번 쓸 수 있고 새 코드를 받으면 이전 코드는 무효가 된다. 글자에 `{입력:기기이전코드}`를 쓰면 화면에 보인다(진행 기록에는 저장하지 않는다).
- **이전 코드로 진행 가져오기**(`transferClaim`): 버튼 대상에 코드를 적는 입력 컨트롤의 키를 정한다. 새 기기가 코드를 낸 게스트를 이어받고 그 진행을 연다. 원래 기기의 게스트는 로그아웃되며 다음 클라우드 작업에서 새 게스트가 된다. 대소문자와 띄어쓰기·하이픈은 상관없다.
- **저장 위치**: 게임 저장 식별자(없으면 시작 맵 ID)마다 슬롯 8개, 슬롯 하나 64KB까지다. 웹은 `web`, Unity는 `unity` 슬롯을 쓴다(두 실행 환경의 진행 형식이 다르다). 스튜디오 편집기의 테스트 플레이는 `preview-` 슬롯을 따로 쓴다. 서버 테이블은 `drizzle/0001_cloud_saves.sql`의 `dw_saves`, `dw_transfers`이며 배포할 때 이 마이그레이션을 적용한다.
- **안내 문구**: 결과 문구(저장함·불러옴·없음·충돌·코드·이전 완료·코드 오류·연결 실패)는 게임 기본 문구라서 **번역 · 언어**에서 바꾸고 번역한다.
- **쓸 수 있는 곳**: 스튜디오 사이트의 플레이 링크(`/play`)와 Unity 빌드(`StudioConnection.Origin` 서버)다. 게임 소스(Web/)를 고친 프로젝트는 격리된 게임 창에서 실행되는데, 그 창은 네트워크와 저장소가 없으므로 스튜디오 페이지가 정해진 요청(`/api/arena/` 세션·저장·이전, `/api/reports`)만 대신 보내고 언어·오류 보고 동의·클라우드 버전 번호를 대신 기억한다. 오프라인 HTML, 다른 곳에 올린 웹 내보내기, 검수 사본의 플레이 창에서는 «이 실행 환경에서는 클라우드 저장을 쓸 수 없어요» 또는 연결 실패를 알린다.

## 플레이어 오류 보고 (동의한 경우)

출시한 게임에서 난 오류를 모아 **검수·빌드 → 플레이어 오류 보고 · 동의한 플레이 수**에서 본다.

- **동의**: 버튼 동작 **오류 보고 동의 바꾸기**(`reports`)를 설정 화면 등에 둔다. 대상은 바꾸기·켜기(`on`)·끄기(`off`)이고, 고른 값은 기기에 게임별로 기억한다(`dreamwalker-reports-v1:<저장 식별자>`). 기본은 꺼짐이라 동의하지 않은 플레이어의 오류는 보내지 않는다. 글자에 `{입력:오류보고}`를 쓰면 «켜짐/꺼짐»이 보인다.
- **보내는 것**: 오류 메시지(300자), 호출 기록(2000자, 주소의 도메인과 쿼리는 서버가 지움), 게임 버전, 맵 ID, 기기 종류(웹은 브라우저 이름·주 버전·OS 종류, Unity는 기기 모델과 OS), 그리고 플레이 1회 카운트다. 플레이어 식별, 입력, 세이브, IP는 저장하지 않는다. 웹은 공개 플레이 링크에서만(스튜디오 편집기 테스트 플레이 제외), Unity는 플레이어 빌드에서만(에디터 제외) 보내고, 플레이마다 서로 다른 오류 10개까지다.
- **묶음**: 서버는 실행 환경, 숫자를 접은 메시지, 첫 호출 위치로 같은 오류를 한 묶음으로 세고 처음·마지막 시각과 최근 버전·맵·기기를 남긴다. 묶음은 1000개까지이며 넘으면 새 종류는 저장하지 않는다(기존 묶음은 계속 센다). 한 주소에서 1분에 30건까지 받는다. 편집 팀원만 목록(최근 200묶음, 14일 플레이 수)을 보고 **해결로 표시**·**모든 오류 보고 지우기**로 정리한다.
- **서버**: `drizzle/0002_error_reports.sql`의 `dw_reports`, `dw_play_days`를 배포할 때 적용한다. 공개 경로는 `POST /api/reports`, `POST /api/reports/session`, 스튜디오 경로는 `GET /api/report-groups`, `POST /api/report-resolve`다.

## 시작하기 · 기능 지도 · 도움말

- **시작하기**(프로젝트 → 시작하기): 이 기기에서 처음 스튜디오를 열면 여기서 시작한다(그다음부터는 마지막에 쓴 도구가 열린다). 오른쪽 **게임 설정**에서 게임 이름, 플레이 저장 식별자(진행 저장·클라우드 저장·언어 기억을 묶는 이름, 출시 뒤에는 바꾸지 않는다), 시작 맵, 기본 키보드 조작 끄기를 바꾸고, 게임 시작 순서·언어·소리 설정으로 바로 간다.
- **제작 순서**: 게임 이름·저장 식별자 → 캐릭터 → 모션 → 맵 → 대사 → 시작 화면·HUD·메뉴 → 홈 화면·설정 화면 → 아이템·의뢰 → 상점·뽑기 → 번역 → 운영 버튼 → 출시 점검 → 빌드의 13단계를 프로젝트 내용으로 바로 계산해 완료·할 일·선택으로 보여 주고, **열기**로 그 일을 하는 곳을 연다.
- **기능 지도**: 모든 도구와 주요 기능 74가지를 한 화면에 보여 준다. 누르면 그 도구가 열리고 해당 부분이 펼쳐져 깜박인다. 같은 목록(`src/studio-guide.js`의 `STUDIO_GUIDE`)으로 **작업 찾기**(Ctrl+K)에서 «천장», «언어 추가», «APK»처럼 하려는 일로 찾고, 도구마다 **도움말**(위쪽 버튼, 빠른 도구의 «도움말», F1)이 그 도구에서 할 수 있는 일을 보여 준다. 브라우저 검사가 목록의 모든 기능이 실제 도구에 있는지 확인한다.
- **게임 소스**: 파일 목록 필터와 상관없이 «웹 게임 실행»과 «Unity 프로젝트» 내보내기가 함께 보인다.

## 쉬운 모드와 스튜디오 · Unity의 역할

프로그래밍을 모르는 사람이 게임 내용을 만들 때 쓰는 보기 방식이다. 프로젝트 데이터는 바꾸지 않고 이 기기의 화면만 바꾼다. 무엇도 지워지지 않고 언제든 되돌린다.

- **켜기**: 이 기기에서 처음 **시작하기**를 열면 «쉬운 모드로 시작»과 «전체 기능으로 시작» 가운데 하나를 고른다. 그 뒤에는 도구 목록의 **쉬운 모드로 보기 / 전체 기능 보기**로 바꾼다. 선택은 이 기기에만 저장한다. 주소 끝에 `?level=easy`를 붙인 링크를 보내면 받은 기기가 쉬운 모드로 열린다.
- **넣어 두는 것**: 개발 담당자의 도구 세 개(게임 소스, 전투 규칙 · Unity, 네트워크 검사)와 검수·빌드·비교·프로젝트 간 주고받기 구역이다. 기능 지도 74가지 가운데 22가지가 해당한다. **검수·빌드**에는 출시 점검, 플레이 검수 기록, 플레이어 오류 보고, 오프라인 HTML 내보내기가 남고(펼칠 구역 40여 개 → 2개), **버전 · 백업**에는 버전 복원과 백업이 남는다. 비어 있는 프리셋·프리팹 보관함도 넣어 두고, 저장한 것이 있으면 보인다. 카메라·연출 시간표·회피 수치처럼 프로그래밍 없이 쓰는 구역은 그대로 둔다. 목록은 `src/easy-mode.js`의 `EASY_HIDDEN` 한 곳에 있다.
- **넣어 둔 것 열기**: **작업 찾기**는 넣어 둔 도구와 기능을 «전체 기능»이라고 표시해 목록 뒤쪽에 보여 주고, 누르면 연다. 넣어 둔 도구를 열면 위쪽에 이유와 «시작하기로»·«전체 기능 보기»가 나온다. 링크로 연 구역은 그 도구를 떠날 때까지 보인다. 도구의 **도움말**은 그 도구에서 넣어 둔 기능 이름을 알려 준다.
- **시작하기**: 제작 순서의 마지막 단계가 «게임 파일로 받기»(검수·빌드의 오프라인 HTML 내보내기)가 되고, 기능 지도는 남은 도구와 기능만 보여 준다.
- **값 넣기** (두 모드 모두): UI 디자인에서 텍스트·버튼의 «표시 문구» 아래 목록에서 재화 보유량, 캐릭터 프로필 항목, 플레이어가 입력한 값, 지금 언어 이름을 고르면 `{재화:…}` 같은 표시를 커서 자리에 넣는다. 프로젝트에 있는 것만 나오고, 캐릭터 이름·스킬 게이지 요소에서는 게임이 바꿔 주는 프로필 항목만 나온다. 표시 안의 재화 이름은 내부 ID라서, 목록 아래에 «지금 문구에 든 값: 재화 보유량 · 결정»처럼 말로 풀어 보여 주고, 게임이 값으로 바꾸지 못하는 표시(잘못 적은 것, 지운 재화)는 따로 알려 준다. 화면 그림에는 새 플레이어가 보는 값(재화의 시작 수량, 입력의 처음 값)으로 보인다.
- **틱을 초로** (두 모드 모두): 틱을 적는 숫자 칸 아래에 초로 바꾼 값이 보인다(60틱 = 1초).
- **용어 풀이** (두 모드 모두): 도구의 **도움말**이 그 화면에 나오는 말(틱, HUD, 앵커, 피벗, 천장, 서버 지갑 등 33개 가운데 해당하는 것)을 풀어 준다.
- **설정값 복사**: «Unity 웹 빌드 준비 방법»의 설정값과 시크릿 이름에 복사 버튼이 있다(값이 아니라 이름만 있다).

| 플레이 | «▶ 테스트 플레이»(초안 즉시), 올라온 웹 빌드가 있으면 «Unity ▶» | Unity 편집기 플레이, 실기기 성능 확인 |
| 내보내기 | 오프라인 HTML 한 파일, 백업 | APK·스토어 제출용 빌드, 클라우드 빌드 설정(한 번) |
| 온라인 | 클라우드 저장·오류 보고 버튼 놓기, 친선전(전체 기능의 전투 규칙 · Unity에서 게시) | 계정 로그인, 실시간 대전·협동, 거래소 |

스튜디오에서 저장한 내용은 Unity 게임이 그대로 읽고, Unity에서 고친 코드와 만든 씬·프리팹은 Unity 창의 «Unity 변경 찾기 · 스튜디오로 보내기»로 스튜디오(게임 소스)에 돌아온다. 그래서 게임 내용은 스튜디오에서, 새 기능은 Unity에서 만든다. 웹 플레이도 같은 기능을 보여 주려면 Unity의 C#과 함께 웹 쪽 JavaScript를 고친다.

## 출시 점검과 대본 도구

- **출시 점검**(검수·빌드 맨 위): 저장을 막는 오류와 화면 흐름 오류, 시작 맵에서 갈 수 없는 맵, 어디에서도 시작하지 않는 대화와 빈 대사, 얻을 방법이 없는 아이템, 시작 수량이 0이고 상품·뽑기·의뢰로도 얻을 수 없는 재화, 뽑기 버튼·«확률 정보 보기» 버튼이 없는 뽑기, 팔지 않는 상품, 원화 상품이 있는데 서버 지갑이 꺼진 경우, 언어별 번역 필요·원문 바뀜 수, 언어 바꾸기·오류 보고·클라우드 저장 버튼이 없는 경우, 그림 없는 캐릭터, 플레이 저장 식별자가 없는 경우를 한 목록으로 보여 준다. 항목마다 **열기**로 고칠 도구로 가고, 저장 식별자는 **지금 시작 맵 ID로 고정**으로 바로 정한다(지금까지의 저장 키와 같아서 기존 진행을 그대로 읽는다). 맵·개체·캐릭터·화면·대화·줄 수와 대사 글자 수, 읽는 데 걸리는 대략의 시간(분당 500자)도 함께 보인다.
- **대본으로 쓰기**(대사 편집 → 대본으로 쓰기 · 내보내기): `이름: 대사`, `이름(표정): 대사`, 이름 없는 줄(내레이션), `* 선택지`·`- 선택지`(위 줄의 선택지, 모두 다음 줄로 이어짐), `// 메모` 형식의 대본을 붙여 넣어 새 대화를 만들거나 지금 대화 끝에 잇는다. 캐릭터 이름이 아닌 이름은 화자 표시 이름이 되고, 없는 표정·선택지 개수·줄 수 한도는 행 번호와 함께 알려 준다. **이 대화를 대본으로**는 같은 형식으로 되돌려 교정용으로 쓰고(콜론이 든 내레이션은 `내레이션:`을 붙여 다시 읽어도 같다), **음성 녹음 대본 CSV**는 말하는 줄마다 줄 ID·화자·표정·대사·음성 연결 여부를 내보낸다.
- **작업 찾기**에서 아이템·의뢰·재화·상품·뽑기도 찾아 연다.

## 홈 화면 · 대기 화면 · 설정과 메뉴 동작

UI 디자인 → **게임 화면**의 버튼 하나로 만들고, 다시 누르면 그 화면을 연다. 만든 화면은 일반 화면처럼 고치고 지울 수 있다. 새 프로젝트에는 들어가지 않는다.

- **홈 화면 (로비)**: 왼쪽에 고른 캐릭터 초상·이름, 오른쪽에 출격·캐릭터 교대·진행 저장·시작 화면으로 버튼이 있는 화면을 만들고 홈 역할로 연결한다. 게임 시작 순서는 **시작 화면 → 캐릭터 선택 → 홈 화면 → 로딩 → 맵**이고 비운 화면은 건너뛴다(«게임 시작 순서 · 화면 연결»에서 바꾼다). 홈 화면에서 «뒤로»는 시작 화면으로 가고 맵으로 빠지지 않는다. 홈 화면 위에 연 화면은 «뒤로»로 닫는다. 홈 화면에 있는 동안에도 진행이 저장된다. 이전에 «홈 역할 화면»만 지정해 두었던 프로젝트는 이제 그 화면이 시작 순서에 들어간다.
- **설정 화면**: 배경음·효과음·음성 음량 슬라이더, 모든 소리 끄기, 대사 속도(작성한 속도의 50~300%), 대사 자동 진행, 언어·오류 보고 버튼이 있는 화면을 만들고 홈 화면 오른쪽 위에 «설정» 버튼을 단다(다른 버튼과 겹치면 빈 자리로 옮긴다). 입력 컨트롤의 **기기 설정 연결**로 어떤 슬라이더·체크박스든 기기 설정에 연결할 수 있다(음량 0~100%, 대사 속도 10~1000%). 기기 설정은 바꾸는 즉시 적용되고, 저장 기록·클라우드 사본과 따로 그 기기에 게임별로 남는다(`dreamwalker-settings-v1:<저장 식별자>`, Unity는 PlayerPrefs의 같은 키). 음량은 제작자가 정한 오디오 믹서 값에 곱해진다. 자동 진행은 선택지가 없는 줄에서 글자가 다 나온 뒤 1.2초 + 글자당 0.05초를 기다렸다 넘어간다.
- **대기 화면**: 입력 없이 30초가 지나면 홈 화면(홈 화면이 없으면 모든 화면) 위에 캐릭터를 크게 보여 주고, 화면 아무 곳이나 누르면 닫힌다. 표시 조건 **입력 없이 시간 경과 (대기)**의 «입력 없이 기다릴 시간»과 «기다릴 화면»으로 바꾼다. 터치·키 입력마다 다시 센다. 기다리던 화면을 지우면 그 조건도 함께 지운다.
- **화면 배경음**: «화면 역할 · 배경»에서 고른 소리는 그 화면이 보이는 동안 맵 배경음 대신 나온다(시작·홈 화면 음악).
- **버튼 동작**: **홈 화면으로**(홈 화면이 없으면 시작 화면), **플레이 시작 (로딩 후 맵)**(끝난 맵은 다시 시작), **진행 저장**·**저장한 진행 불러오기**(알림이 화면에 남는다), **게임 종료**(진행을 저장하고 닫는다. 웹은 게임 창을 닫고 Unity Android는 앱을 끝낸다), **웹 링크 열기**(`https://` 주소나 `mailto:` 메일 주소만. 이용약관·개인정보 처리방침·문의에 쓴다. 웹은 새 탭, Unity는 기기 브라우저로 연다), **상태 전환**(켜져 있으면 끄고 꺼져 있으면 켠다)이 더해졌다. 후속 동작으로 묶어 «저장하고 홈으로»처럼 쓸 수 있다.

## 화면이 열리는 조건

**화면 역할 · 배경**에서 용도, 배경, 배경음, 역할과 전투 일시정지를 정한다. **이 화면을 표시할 때 → ＋ 표시 조건**에서 게임 시작, 맵 진입, 시간 경과, 입력 없이 시간 경과(대기), 메뉴, 지정 스킬, 교대, 체력 하락, 마지막 적 처치, 대화 시작·종료, 승리·패배 또는 이름을 붙인 이벤트를 지정한다. 맵, 캐릭터, 상태, 반복 횟수와 우선순위로 조건을 좁힐 수 있다. 높은 우선순위가 먼저이고 동률이면 목록 앞쪽 화면이 열린다. 상태와 ‘플레이당 한 번’ 기록은 새 게임을 시작할 때 초기화된다.

예를 들어 설산 광산역 안내창은 사용자 화면을 만든 뒤 **맵 진입 / 설산 광산역 / 플레이당 한 번**으로 설정한다. ‘출동’ 버튼의 첫 동작은 **상태 켜기**, 상태 이름은 ‘안내확인’, 후속 동작은 **게임으로**로 둔다. 별도의 화면은 **대화 종료**로 연결하거나 맵의 **대화 · 이벤트 지점**과 동일한 이름의 이벤트를 수신하도록 지정할 수 있다.

## 소스 편집과 내보내기

**게임 소스**에서 웹 게임의 HTML·CSS·JavaScript 또는 Unity C#·셰이더·설정 파일을 편집하고 추가·이름 변경·삭제·복원한다. 새 웹 파일은 Web/index.html에 연결한다. 편집한 웹 게임은 분리된 프레임에서 실행되며 오프라인 HTML로도 내보낼 수 있다. 내보낸 파일 이름은 플레이 저장 식별자를 쓴다(`<식별자>-Play.html`, `<식별자>-Unity-v<버전>.zip`). **확장 데이터 · JSON**의 내용은 양쪽 게임에서 customJson으로 읽는다. **저장본 → 전체 Unity 프로젝트**는 수정한 소스와 프로젝트 설정, 콘텐츠와 이미지를 ZIP으로 묶는다. Unity C#을 수정한 경우 다음 네이티브 빌드에 적용된다.

## Unity 데모

Unity 프로젝트의 전투 데모를 열고 **Dreamwalker Studio** 버튼으로 팀 암호를 입력하면 공유 설정을 불러온다. 기존 데모는 이동·점프·돌진·기본 공격·적 체력을 갱신한다. **Play studio maps**는 저장된 시작 맵에서 네이티브 콘텐츠 플레이를 연다. 편집 중 새 버전이 저장되면 **Restart with latest version**으로 전환한다. Unity는 기존 이동·검격·피격 컴포넌트와 맵으로 생성한 충돌체를 사용하므로 브라우저와 물리 조작감에 차이가 있을 수 있다.

**저장본 → Unity 콘텐츠 팩**은 최근 공유 버전의 JSON과 참조하는 이미지를 포함한다. 이 PR의 런타임 코드가 있는 Unity 프로젝트에 ZIP의 Assets 폴더를 합치면, 생성된 전투 데모가 Resources의 팩을 읽어 오프라인으로 실행한다. 팩에는 팀 암호·세션·편집 서버가 포함되지 않는다. 기존에 내보낸 동일 프로젝트 팩을 교체할 때는 이전 DreamwalkerStudio 리소스 폴더를 백업하고 교체한다. Unity Editor에서 씬이 아직 없으면 Tools → Dreamwalker → Create Combat Demo Scene으로 생성한다.

## Unity 게임 화면 (uGUI)

Unity 런타임의 게임 화면(시작·캐릭터 선택·로딩 화면, HUD, 대사창, 이 줄 화면, 입력 필드와 선택 목록, 인벤토리·의뢰 목록, 컷인과 외침, 장면 전환, 온라인 친선전, 데모 HUD)은 uGUI(`com.unity.ugui` 2.0.0)로 그린다. 화면 하나가 화면 해상도 그대로의 Screen Space Overlay 캔버스이고, 그리기 호출마다 지난 프레임의 오브젝트를 다시 쓰며 바뀐 값만 적용한다. 둥근 상자·테두리·그림은 각각 메시 하나로 그린다. 목록은 손가락으로 끌어 스크롤하고(ScrollRect), 입력 필드는 기기 키보드를 쓴다(InputField).

- 글자와 고정 크기는 스튜디오 미리보기처럼 CSS 픽셀 기준에 화면 밀도를 곱한다. 고해상도 태블릿에서 글자가 미리보기보다 작게 보이던 차이를 없앴다. 웹 공식과 같은 표를 `npm test`와 .NET 검사가 함께 확인한다.
- 데스크톱 마우스는 터치와 같은 경로로 처리해 클릭이 탭과 같게 동작한다. 대사·목록·입력 위젯 위의 터치는 아래에 겹친 버튼으로 넘어가지 않는다.
- 릴리스 빌드(개발 빌드가 아닌 APK)에서는 스튜디오 연결 패널을 숨긴다. 플레이 중에는 60 FPS를 목표로 하고 화면이 꺼지지 않으며, Escape(안드로이드 뒤로 가기)로 열린 메뉴·화면을 닫는다. 웹 게임의 Escape와 같다. 플레이를 마치면 원래 값으로 돌린다.
- Unity 에디터에서 **Tools → Dreamwalker → 이전 IMGUI 화면으로 비교**를 켜면 다음 Play부터 이전 IMGUI 화면으로 그려 같은 콘텐츠를 비교할 수 있다. 플레이어 빌드는 항상 uGUI다.
- 런타임과 에디터 스크립트는 어셈블리 정의(`Dreamwalker.Runtime`, `Dreamwalker.Editor`)로 나뉘고, Unity Test Framework 테스트가 `Assets/Dreamwalker/Tests`에 있다. 에디터 테스트는 uGUI 그리기(오브젝트 재사용·그리는 순서·클릭·스크롤·입력·도형 메시)를, 플레이 테스트는 스튜디오 기본 프로젝트로 시작 화면부터 HUD·메뉴까지 화면에 나온 글자를 확인한다.

## Unity 클라우드 빌드와 웹 플레이

Unity 편집기는 태블릿에서 돌지 않는다. 그래서 클라우드에서 Unity가 이 저장소를 빌드하고, 스튜디오가 그 결과를 받아 쓴다. 이 저장소의 검사는 스튜디오·서버·올리기 스크립트와 Unity 스크립트 컴파일까지 확인했고, 실제 Unity 빌드는 만들지 못했다(Unity 계정이나 라이선스가 필요하다). 첫 실제 빌드에서 Unity 쪽 문제가 나올 수 있다.

- **Unity로 테스트 플레이**: Unity 웹 빌드가 올라와 있으면 위쪽에 **Unity ▶** 버튼이 생기고, **버전 · 백업 → Unity 연동 · 웹 빌드로 테스트 플레이**에 빌드 시각·Unity 버전·커밋이 보인다. 누르면 편집 중인 초안(저장 전 내용 포함)과 그 그림·소리를 Unity 웹 빌드에 넘겨 실제 Unity 런타임으로 플레이한다. 맵 편집에서 누르면 편집 중인 맵에서 시작한다. 맵·수치·대사·화면은 다시 빌드하지 않아도 반영되고, Unity C#을 바꾸면 다시 빌드한다. **기록**에서 Unity의 로그와 오류를 보고 **기록 복사**로 복사한다.
- **분리된 창**: 올라온 빌드는 스튜디오 페이지와 분리된 창에서만 실행한다(편집한 웹 게임을 실행하는 창과 같은 방식). 그 창은 네트워크·브라우저 저장소·스튜디오 페이지에 접근할 수 없고, 스튜디오가 빌드 파일 네 개와 초안의 그림·소리를 직접 넘긴다. 그래서 Unity 플레이에서는 클라우드 저장·서버 지갑·친선전·오류 보고 같은 서버 기능이 동작하지 않고 진행도 남지 않는다(매번 처음부터 시작).
- **글꼴**: 웹 플레이어에는 기기 글꼴이 없어서 프로젝트에 넣은 Pretendard(SIL Open Font License, `Assets/Dreamwalker/Fonts`)로 모든 글자를 그린다. 한글·가나·라틴 글자가 있고 한자는 없다. Android 등 다른 플랫폼은 이전처럼 기기 글꼴을 쓴다.
- **빌드 방법 1 · Unity Build Automation** (PC 없이 Unity 대시보드에서 설정):
  1. 스튜디오 **버전 · 백업 → Android APK 빌드 · 실기기 성능 → 실행기 연결**에서 연결 키를 받는다.
  2. Unity 대시보드 **DevOps → Build automation → Configurations**에서 이 GitHub 저장소를 연결하고(저장소 읽기 권한 토큰), 브랜치 `feature/tablet-production-studio`, **Auto detect Unity version**으로 WebGL 대상을 만든다.
  3. 대상의 **Advanced settings → Script hooks**에 Pre-Export Method `DreamwalkerCloudBuild.PreExport`, Post-Build Script `Studio/scripts/unity-cloud-upload.sh`를 넣고, **Environment variables**에 `DREAMWALKER_RUNNER_KEY`(1의 키)를 넣는다. 키는 저장소·프로젝트 데이터에 넣지 않는다.
  4. 빌드를 실행한다. 끝나면 스크립트가 웹 빌드를 스튜디오에 올린다.
  5. Android 대상에도 같은 값을 넣으면 APK가 스튜디오에 올라온다. **Development build**를 켜야 앱에 스튜디오 연결 패널이 나온다.
- **빌드 방법 2 · GitHub Actions**: 아래 라이선스 시크릿을 넣으면 `unity-editor.yml`이 웹 빌드와 개발용 APK를 만들어 스튜디오에 올린다. 스튜디오는 GitHub가 서명한 실행 정보(이 저장소, 제작 브랜치, 이 워크플로)를 확인하므로 키가 필요 없다.
- **개발용 APK**: **Unity 연동**의 **Unity 개발용 APK 받기**로 내려받아 설치한다. APK에는 프로젝트 내용이 없고, 앱의 **Dreamwalker Studio** 패널에서 팀 암호로 연결해 저장한 팀 버전을 불러온다.
- **순서**: 스튜디오를 이 버전으로 먼저 배포한다. 그 전의 스튜디오에는 올리기 경로가 없어서, 빌드는 실패하지 않고 «아직 Unity 빌드를 받지 않는다»는 안내만 남긴다.
- **서버**: 올리기는 `POST /api/unity-web/begin`(실행기 키 또는 GitHub 실행 정보) → `upload/<loader·framework·data·code·apk>` → `publish`(APK는 `publish-apk`)이고, 읽기는 팀 세션의 `GET /api/unity-web/status`와 `file/<빌드 ID>/<파일>`이다. 파일 하나는 90MB까지이고, 새 빌드가 올라오면 이전 빌드를 지운다. 웹 빌드는 Unity 압축을 끄고 만들며(`StudioCloudBuild.Prepare`), 올릴 때 gzip으로 줄이고 브라우저가 푼다.
- **알아 둘 것**: Build Automation을 Personal 요금제에서 쓸 수 있는지, 6000.0.23f1 패치를 제공하는지는 Unity 문서에 명시가 없다. 한 달 무료 빌드 시간(2026년 기준 Windows 200분, Mac 100분)을 넘으면 과금된다. 웹 플레이어와 APK는 성능과 소리 지연이 다르므로 최종 확인은 APK로 한다. 스튜디오의 «저장본 → 전체 Unity 프로젝트» ZIP에는 글꼴 파일이 들어가지 않으므로, 그 ZIP으로 웹 빌드를 만들 때는 저장소의 `Assets/Dreamwalker/Fonts`를 함께 넣는다.

## Unity 에디터 테스트와 APK 빌드 (GitHub Actions)

`unity-editor.yml` 워크플로는 실제 Unity 6000.0.23f1 에디터(GameCI 컨테이너)에서 위 테스트를 실행하고, 제작 브랜치에 반영되거나 수동으로 실행하면 개발용 APK(`dreamwalker-development-apk` 아티팩트)와 웹 빌드(`dreamwalker-unity-web` 아티팩트)를 만들어 스튜디오에도 올린다. 웹 빌드는 테스트를 기다리지 않는다. Unity 라이선스가 필요하므로 저장소의 **Settings → Secrets and variables → Actions**에 다음을 추가해야 동작한다. 없으면 작업을 건너뛰고 그 사실을 알린다.

- `UNITY_LICENSE`: Unity Hub로 이 계정의 라이선스를 활성화한 컴퓨터의 `Unity_lic.ulf` 파일 내용 전체. Windows는 `C:\ProgramData\Unity\Unity_lic.ulf`, macOS는 `/Library/Application Support/Unity/Unity_lic.ulf`, Linux는 `~/.local/share/unity3d/Unity/Unity_lic.ulf`에 있다.
- `UNITY_EMAIL`, `UNITY_PASSWORD`: 같은 Unity 계정의 이메일과 암호.

라이선스 없이도 `node scripts/unity-compile-check.mjs`가 어셈블리 정의대로 런타임·에디터·테스트 어셈블리와 uGUI(에디터 내장 소스)·Test Framework(패키지 레지스트리)를 편집기·Android 플레이어·웹 플레이어 세 구성으로 컴파일해 확인한다.

## Unity에서 만든 작업을 스튜디오로

태블릿의 **Unity로 보내기 → Unity 처음 연결 → 연결 코드 만들기**로 받은 코드를 Unity의 **Tools → Dreamwalker → 태블릿 변경 가져오기** 창에 입력해 연결한다. 같은 창의 **Unity 변경 찾기**는 Unity 프로젝트의 `Assets`·`Packages`·`ProjectSettings`를 스튜디오의 현재 게임 소스와 비교한다. 텍스트로 저장된 스크립트·씬·프리팹·머티리얼·애니메이션·설정과 `.meta` 파일은 새 파일·수정·Unity에 없음(삭제)으로, PNG·JPG(2MB까지)와 WAV·OGG·MP3(8MB까지)는 이미지·소리로 표시한다. 고른 항목을 **선택 N개 스튜디오로 보내기**로 보낸다. 한 번에 400개, 24MB까지 보낼 수 있고, 새로 보내면 이전에 받은 변경을 대신한다.

스튜디오의 **게임 소스 → Unity에서 보낸 변경**(또는 Unity로 보내기 창의 **Unity에서 보낸 변경 보기**)에서 파일별 줄 차이, 그림 미리보기, 소리 재생을 확인하고 적용할 항목을 고른다. Unity가 비교한 뒤 스튜디오에서도 바뀐 파일과 삭제는 처음에 선택되지 않는다. Unity가 파일·폴더마다 만드는 `.meta`(GUID)는 한 묶음으로 표시되며, 씬·프리팹이 스크립트를 찾는 데 필요하므로 함께 보내는 것이 기본이다. **선택한 변경 N개를 초안에 적용**한 뒤 저장하면 팀 버전에 들어간다. 소스는 **저장본 → 전체 Unity 프로젝트** ZIP에 포함되고, 이미지·소리는 **프로젝트 에셋**의 `Unity` 폴더에 추가되어 맵·캐릭터·UI에서 고를 수 있다. 이미지·소리는 Unity의 원래 경로로 ZIP에 다시 넣지 않는다.

- 스튜디오가 생성하는 `Assets/Resources/DreamwalkerStudio`와 가져오기 기록은 보내지 않는다. 바이너리로 직렬화한 씬·프리팹, 20만 자를 넘는 텍스트, FBX·PSD 같은 형식은 Unity 창의 제외 목록에 이유와 함께 표시된다. Unity 6 기본값인 **Asset Serialization: Force Text**에서 씬·프리팹을 보낼 수 있다.
- 게임 소스 한도(파일 600개, 합계 400만 자, 파일 하나 20만 자)를 넘는 적용은 막고 일부만 고르도록 안내한다. 큰 Unity 프로젝트 전체를 보관하는 용도가 아니라 스튜디오와 함께 다루는 스크립트·씬·설정과 리소스를 옮기는 용도다.
- Unity 연결은 보내기와 스튜디오 소스 목록(경로와 해시) 조회만 할 수 있다. 받은 변경의 확인·적용·지우기는 편집 권한이 있는 태블릿만 한다. 팀 암호를 바꾸면 이전 연결과 받은 변경은 쓰지 않는다. 검수 사본에서 적용해도 원본 제작실의 받은 변경은 남는다.

## 개발 및 저장 구조

Studio 폴더에서 Node 22 이상과 bash, unzip이 있는 환경으로 npm test를 실행한다. 테스트가 Worker를 빌드한 뒤 모델 마이그레이션, 참조 무결성, 전투·대화·출구·메뉴, 암호·공유 버전 충돌, 이미지 권한, Unity ZIP의 CRC와 이미지 내용을 검사한다.

웹과 Unity가 같은 규칙을 쓰는 부분은 스튜디오에서 만든 표로 .NET 검사(`scripts/native-check`)가 비교한다: 번역(`unity-locale.mjs`), 뽑기(`unity-gacha.mjs`), 링크·기기 설정·대사 속도·자동 진행·대기 화면(`unity-menus.mjs`). 표는 각 스크립트로 다시 만들고 `--check`로 최신인지 확인한다.

Unity 스크립트 컴파일은 라이선스 없이 `node scripts/unity-compile-check.mjs --fetch <캐시 폴더>`로 확인한다. `ProjectVersion.txt`의 Unity 버전에 맞는 공식 Linux 에디터 압축에서 관리 어셈블리만 내려받고, .NET 8 C# 컴파일러로 에디터(런타임과 Editor 폴더)·Android 플레이어·웹 플레이어 구성을 컴파일한다. 설치된 Unity가 있으면 `<Unity>/Editor/Data` 경로를 직접 넘긴다. 플레이 모드 실행과 화면 확인은 Unity 에디터에서 한다.

**프로젝트 규모와 버전 저장**: 한 게임에 캐릭터 120명, 맵 200개(맵당 개체 400개), 대화 400개(대화당 줄 300개), 화면 120개(화면당 위젯 96개), 표정 48개·프로필 항목 32개까지 담는다. 저장 한 번은 8MB까지 받는다. 서버의 `project` 기록에는 현재 프로젝트와 최근 30개 버전의 번호·시각만 두고, 이전 버전은 각각 `project/rev/<번호>`로 따로 보관해 필요할 때 `/api/revision?rev=<번호>`로 읽는다. 30개를 넘은 버전은 저장할 때 지운다. 이전 형식(버전 프로젝트를 기록 안에 함께 둔 형식)은 그대로 읽고 다음 저장 때 옮긴다. 저장 전 초안은 기기의 IndexedDB에 두며, 페이지를 닫을 때는 크기가 맞으면 localStorage에도 바로 남긴다. 캐릭터 100명·맵 160개(맵당 개체 62개)·대화 380개(대화당 40줄)인 3.7MB 프로젝트로 저장·불러오기를 검사한다.

프로젝트의 schema 값은 4다. v3 프로젝트와 버전 기록도 읽을 때 업그레이드한다. 장면과 캐릭터 등은 안정적인 ID로 연결한다. 기존 형식의 맵과 수치, 업로드한 백설과 배경 이미지는 읽을 때 변환한다. 이미지는 로그인한 사용자가 접근하는 R2에 내용 해시로 저장한다. Unity 기본 소스를 갱신할 때는 Studio에서 node scripts/sync-unity.mjs .. 를 실행한다. 서버는 저장하기 전에 참조 ID와 신규 이미지의 존재를 검사한다. 사용자 제작 데이터와 팀 암호는 소스 저장소에 넣지 않는다.

배포 환경에는 R2 바인딩 BUCKET과 소유자 이메일을 소문자화한 SHA-256 값 STUDIO_OWNER_EMAIL_SHA256이 필요하다. 소유자 확인 값은 호스팅의 비밀 환경 변수로 설정한다.

## 소유자 계정의 제작 GPT

제작 GPT의 **내 GPT 설정**에 사용 방식을 저장한다. 태블릿에서는 **내 ChatGPT 대화**로 요청을 만들고 같은 계정의 ChatGPT에서 모델을 선택한다. 드림워커 스튜디오 플러그인이 선택한 화면을 읽고 답변을 돌려준다. 직접 만든 GPT의 주소를 저장하거나 요청 전문과 JSON 답변을 복사해 주고받을 수도 있다.

**내 PC의 Codex**를 선택하면 로그인된 개발 PC가 제공하는 모델과 추론 강도를 스튜디오에서 지정할 수 있다. 같은 소유자 계정으로 공식 Codex CLI에 로그인하고, Node.js 22 이상에서 제작 GPT 화면의 연결 파일을 내려받아 `node dreamwalker-gpt.mjs`로 실행한다. 5분 연결 코드를 입력하고 연결기를 실행해 두면 태블릿에서도 요청과 답변을 같은 화면에서 처리한다. 해제 후에는 새 코드로 `node dreamwalker-gpt.mjs --pair`를 실행한다.

개인 설정은 게임 저장본과 별개다. 소유자가 보낸 최근 요청 한 건은 한 시간 동안 확인할 수 있고 **최근 요청 지우기**로 지울 수 있다. 답변의 변경안은 미리보기에서 검토하고 초안에 적용한다. 사이트 운영자가 별도로 키를 설정한 경우에만 **스튜디오 API**를 선택할 수 있다.

### 편집 중에 GPT 사용하기

편집기 위쪽의 **작업 GPT**를 열면 맵·캐릭터·대사·전투 규칙·UI에서 작업 대상을 바꿔 가며 질문할 수 있다. 전송 시점의 선택 대상과 관련 수치가 질문에 포함된다. 화면·메뉴 변경은 미리보기에서 **변경안을 초안에 적용**한 뒤 평소처럼 저장한다.

같은 소유자 계정의 ChatGPT에서 Dreamwalker Studio를 선택하고 **드림워커 제작 GPT 열어 줘**라고 입력한다. 제작 패널에서 바로 질문하거나 **이 대화 연결**을 눌러 웹 편집기의 **작업 GPT**와 연결한다. 사용 방식을 **내 ChatGPT 대화**로 선택하면 편집기에서 보내는 질문이 연결된 대화에서 처리되고 답변이 편집기에 표시된다. 이 방식은 연결된 제작 패널이 동작하는 동안 사용할 수 있다. 태블릿에서 앱이 백그라운드 탭을 멈추면 분할 화면으로 두 창을 열 수 있다. 연결은 두 시간 후 끝나며 양쪽에서 언제든 해제할 수 있다.

## Claude와 제작하기

편집기 위쪽의 **Claude**에서 공유 프로젝트 연결 키를 발급할 수 있다. Claude에서 현재 게임을 읽고 변경을 미리 본 뒤 공유 버전으로 저장한다. **저장 전 초안을 Claude와 주고받기**에서는 선택한 항목과 작업 요청을 복사하고, Claude의 JSON 답변을 검토해 기기 초안에 적용한다. **Claude Code로 스튜디오 개조**에는 제작 도구 자체를 수정할 때 사용할 저장소와 요청 문구가 있다. [연결과 사용 방법](CLAUDE_CODE.md)
