# Dreamwalker Studio

[제작 스튜디오](https://dreamwalker-snowfield-studio.congenialcockatoo.chatgpt.site/) · [저장 버전 플레이](https://dreamwalker-snowfield-studio.congenialcockatoo.chatgpt.site/play)

갤럭시 탭 브라우저에서 장면을 만들고 팀 암호로 공유하는 Dreamwalker 제작 도구다. 소유자는 ChatGPT 계정으로 로그인하면 바로 편집할 수 있다. 팀원이 참여할 때는 **버전 · 백업 → 팀 암호 설정**에서 8자 이상의 암호를 정한다. 팀원은 이 암호로 편집·플레이할 수 있다. 암호를 바꾸면 기존 세션이 만료된다.

## 제작자가 직접 검수하는 경로

**검수·빌드 → 프로젝트 검수 사본 · 별도 저장 슬롯**에서 원하는 팀 버전이나 초안을 복제한다. 사본은 이 브라우저에 보관한다. 편집하고 저장한 다음 같은 링크를 다시 열면 작업을 이어갈 수 있다. 실제 게임 진행과 검수용 슬롯은 각각 저장한다. **기능별 검증 현황과 직접 시험할 방법**에는 도구 위치, 조작, 확인한 환경과 남은 조건을 표시한다.

제작 보드에서 기획서와 작업을 연결하고, 각 편집기에서 화면·조작·맵·대사·캐릭터·규칙을 수정한다. 기기에서 연 파일은 적용 전에 미리 보며, 선택한 대상에 반영한 뒤 같은 편집기로 돌아간다. 웹·Unity 비교용 입력과 결과 파일은 제작자가 선택한 공유 버전과 콘텐츠 해시에 연결한다. [기능별 검증표와 실기기 재현 절차](VERIFICATION.md)

## Unity 전투 규칙과 온라인 친선전

**전투 규칙 · Unity**에서 예를 들어 백설이 세 번째 공격을 적중할 때 보호막 5를 얻도록 설정할 수 있다. 자기 체력 조건과 재사용 대기를 추가할 수 있다. 준비·판정·회복은 60틱 기준이다. **저장 · 게임 반영** 후 Unity 프로젝트를 내보내면 `Assets/Resources/DreamwalkerStudio/release.json`에 맵과 규칙이 들어간다. 기존 프로젝트에는 새 C# 런타임을 먼저 반영한다. 필드의 규칙 횟수, 보호막과 처치 의뢰는 체크포인트에 저장된다.

소유자가 **저장한 전투 규칙 게시**를 누르면 새 친선전 방이 그 버전을 사용한다. 브라우저에서 **친선전 열기**, Unity의 **Dreamwalker Studio → Online friendly match**로 같은 방에 들어간다. 한 사람이 방을 만들고 상대가 8자리 코드를 입력한다. 각 기기의 게스트 자격으로 진행 중인 방에 다시 들어갈 수 있다.

| 구성 | 담당 코드 | 책임 |
| --- | --- | --- |
| 제작 데이터 | `src/model.js`, `src/combat-editor.js` | 규칙 검증, Unity 내보내기, 공개할 전투 수치 추출 |
| Unity 필드 | `StudioCombatRules.cs`, `StudioWorld.cs` | 네이티브 적중·피격·처치 처리와 진행 저장 |
| 온라인 전투 | `src/arena-simulation.js`, `src/arena-service.js` | 방별 규칙 고정, 서버 시간 기준 판정, 입력 순서와 승패 확정 |
| 플레이어 데이터 | `drizzle/0000_online.sql` | 방 좌석, 승리 보상, 휘장 판매 예치·구매·취소 |
| 온라인 클라이언트 | `StudioOnlineArena.cs`, `src/arena-client.js` | 기기 입력 전송과 서버가 확정한 화면 표시 |

친선전은 이동·기본 공격·점프·회피를 지원한다. 서버가 입력을 받거나 방 상태를 조회할 때 경과한 틱을 계산한다. 클라이언트는 통신이 끝난 뒤 다음 입력을 보낸다. 네트워크 검사에서 제작자가 고른 스킬·자원·재사용 대기를 같은 버전으로 재생하며, 두 좌석의 입력 예측과 서버 승인 후 상태 보정을 대조한다. 상용 경쟁전에는 실시간 다단 충돌·모션 동기화, 실제 단말·회선과 서버 부하 검수가 남아 있다. 거래소 화폐는 대전에서 얻는 게임 내 크레딧이다.

## 패드에서 콘텐츠 제작

1. **캐릭터**에서 새 인물을 추가하거나 기존 캐릭터를 복제한다. 전신과 초상화, 지역·소개, 체력·이동·점프·사거리·공격 배율, 패시브와 1~12개 스킬 슬롯을 편집한다. 각 칸에는 관통 돌진, 단일 연격, 추적 복귀, 영역 공격, 갈고리 접근, 직선 원거리 타격을 연결할 수 있다. 직접 조립한 동작에서는 타격, 접근, 이동, 대기, 회복, 원위치 복귀를 원하는 순서로 조합한다.
2. **대사 편집**에서 화자·대사·선택지를 작성한다. 일반 대사는 다음 줄로 진행하고 선택지는 지정한 줄로 이동하거나 대화를 끝낸다. 대사 순서를 바꿔도 선택지의 연결은 유지된다. **스토리 로드맵**에서는 캐릭터별로 에피소드의 제목과 한 줄 요약, 시작점, 선택지별 도착점, 연결 대화와 배경 맵을 정한다. 기존 대사를 여러 캐릭터가 함께 쓸 수 있다. 카드에서 경로를 읽어 보고 HUD나 메뉴에 **현재 캐릭터 스토리** 버튼을 추가하면 게임에서도 열린다.
3. **맵 편집**에서 배치 도구를 선택한 뒤 캔버스를 눌러 개체를 놓는다. 선택 도구로 옮기거나 좌표를 입력한다. 가로 길이 100~3200(한 화면은 100), 발판 너비, 적별 그림·체력·피해·추격 속도·감지 거리·공격 간격, 배경·소품, 시작 캐릭터, 대화 지점과 출구를 설정한다. 맵 연결 설정에서 입장·출구 대화, 목적지, 적 처치 조건, 화면, 게임 시작 맵을 지정한다.
4. **UI 디자인**에서 HUD, 메뉴, 대화 또는 사용자 화면을 만든다. **＋ 버튼 추가**로 버튼을 놓고 터치로 끌거나 좌표와 크기를 %로 입력한다. 그림·글자·테두리·모서리·누른 색·앞뒤 순서와 상태별 표시/활성 조건을 편집한다. **버튼 동작**과 **후속 동작**으로 상태 변경, 다른 화면 열기, 이전 화면 복귀, 맵 이동, 대화, 교대, 스킬 사용과 이벤트 발송을 순서대로 실행한다.
5. **테스트 플레이**는 선택한 맵과 편집 중인 초안으로 시작한다. **저장 · 게임 반영**은 팀 버전을 만든다. 플레이 링크는 저장된 시작 맵을 연다. 진행 중인 플레이는 시작할 때 받은 버전을 사용한다. PC에서 A/D나 방향키로 이동하고 Space로 점프하며 Z/X/C/V/B로 공격·스킬을 사용한다.
6. **버전 · 백업**에서 최근 8개 저장본을 초안으로 복원하거나 이미지 포함 JSON을 내보낸다. 팀원이 같은 버전을 먼저 저장하면 두 번째 저장은 거절된다. 작업 내용을 백업한 뒤 최신 버전을 열어 변경 사항을 합칠 수 있다.

## 화면이 열리는 조건

**화면 역할 · 배경**에서 용도, 배경, 역할과 전투 일시정지를 정한다. **이 화면을 표시할 때 → ＋ 표시 조건**에서 게임 시작, 맵 진입, 시간 경과, 메뉴, 지정 스킬, 교대, 체력 하락, 마지막 적 처치, 대화 시작·종료, 승리·패배 또는 이름을 붙인 이벤트를 지정한다. 맵, 캐릭터, 상태, 반복 횟수와 우선순위로 조건을 좁힐 수 있다. 높은 우선순위가 먼저이고 동률이면 목록 앞쪽 화면이 열린다. 상태와 ‘플레이당 한 번’ 기록은 새 게임을 시작할 때 초기화된다.

예를 들어 설산 광산역 안내창은 사용자 화면을 만든 뒤 **맵 진입 / 설산 광산역 / 플레이당 한 번**으로 설정한다. ‘출동’ 버튼의 첫 동작은 **상태 켜기**, 상태 이름은 ‘안내확인’, 후속 동작은 **게임으로**로 둔다. 별도의 화면은 **대화 종료**로 연결하거나 맵의 **대화 · 이벤트 지점**과 동일한 이름의 이벤트를 수신하도록 지정할 수 있다.

## 소스 편집과 내보내기

**게임 소스**에서 웹 게임의 HTML·CSS·JavaScript 또는 Unity C#·셰이더·설정 파일을 편집하고 추가·이름 변경·삭제·복원한다. 새 웹 파일은 Web/index.html에 연결한다. 편집한 웹 게임은 분리된 프레임에서 실행되며 오프라인 HTML로도 내보낼 수 있다. **확장 데이터 · JSON**의 내용은 양쪽 게임에서 customJson으로 읽는다. **저장본 → 전체 Unity 프로젝트**는 수정한 소스와 프로젝트 설정, 콘텐츠와 이미지를 ZIP으로 묶는다. Unity C#을 수정한 경우 다음 네이티브 빌드에 적용된다.

## Unity 데모

Unity 프로젝트의 전투 데모를 열고 **Dreamwalker Studio** 버튼으로 팀 암호를 입력하면 공유 설정을 불러온다. 기존 데모는 이동·점프·돌진·기본 공격·적 체력을 갱신한다. **Play studio maps**는 저장된 시작 맵에서 네이티브 콘텐츠 플레이를 연다. 편집 중 새 버전이 저장되면 **Restart with latest version**으로 전환한다. Unity는 기존 이동·검격·피격 컴포넌트와 맵으로 생성한 충돌체를 사용하므로 브라우저와 물리 조작감에 차이가 있을 수 있다.

**저장본 → Unity 콘텐츠 팩**은 최근 공유 버전의 JSON과 참조하는 이미지를 포함한다. 이 PR의 런타임 코드가 있는 Unity 프로젝트에 ZIP의 Assets 폴더를 합치면, 생성된 전투 데모가 Resources의 팩을 읽어 오프라인으로 실행한다. 팩에는 팀 암호·세션·편집 서버가 포함되지 않는다. 기존에 내보낸 동일 프로젝트 팩을 교체할 때는 이전 DreamwalkerStudio 리소스 폴더를 백업하고 교체한다. Unity Editor에서 씬이 아직 없으면 Tools → Dreamwalker → Create Combat Demo Scene으로 생성한다.

## 개발 및 저장 구조

Studio 폴더에서 Node 22 이상과 bash, unzip이 있는 환경으로 npm test를 실행한다. 테스트가 Worker를 빌드한 뒤 모델 마이그레이션, 참조 무결성, 전투·대화·출구·메뉴, 암호·공유 버전 충돌, 이미지 권한, Unity ZIP의 CRC와 이미지 내용을 검사한다.

프로젝트의 schema 값은 4다. v3 프로젝트와 버전 기록도 읽을 때 업그레이드한다. 장면과 캐릭터 등은 안정적인 ID로 연결한다. 기존 형식의 맵과 수치, 업로드한 백설과 배경 이미지는 읽을 때 변환한다. 이미지는 로그인한 사용자가 접근하는 R2에 내용 해시로 저장한다. Unity 기본 소스를 갱신할 때는 Studio에서 node scripts/sync-unity.mjs .. 를 실행한다. 서버는 저장하기 전에 참조 ID와 신규 이미지의 존재를 검사한다. 사용자 제작 데이터와 팀 암호는 소스 저장소에 넣지 않는다.

배포 환경에는 R2 바인딩 BUCKET과 소유자 이메일을 소문자화한 SHA-256 값 STUDIO_OWNER_EMAIL_SHA256이 필요하다. 소유자 확인 값은 호스팅의 비밀 환경 변수로 설정한다.

## 소유자 계정의 제작 GPT

제작 GPT의 **내 GPT 설정**에 사용 방식을 저장한다. 태블릿에서는 **내 ChatGPT 대화**로 요청을 만들고 같은 계정의 ChatGPT에서 모델을 선택한다. 드림워커 스튜디오 플러그인이 선택한 화면을 읽고 답변을 돌려준다. 직접 만든 GPT의 주소를 저장하거나 요청 전문과 JSON 답변을 복사해 주고받을 수도 있다.

**내 PC의 Codex**를 선택하면 로그인된 개발 PC가 제공하는 모델과 추론 강도를 스튜디오에서 지정할 수 있다. 같은 소유자 계정으로 공식 Codex CLI에 로그인하고, Node.js 22 이상에서 제작 GPT 화면의 연결 파일을 내려받아 `node dreamwalker-gpt.mjs`로 실행한다. 5분 연결 코드를 입력하고 연결기를 실행해 두면 태블릿에서도 요청과 답변을 같은 화면에서 처리한다. 해제 후에는 새 코드로 `node dreamwalker-gpt.mjs --pair`를 실행한다.

개인 설정은 게임 저장본과 별개다. 소유자가 보낸 최근 요청 한 건은 한 시간 동안 확인할 수 있고 **최근 요청 지우기**로 지울 수 있다. 답변의 변경안은 미리보기에서 검토하고 초안에 적용한다. 사이트 운영자가 별도로 키를 설정한 경우에만 **스튜디오 API**를 선택할 수 있다.

### 편집 중에 GPT 사용하기

편집기 위쪽의 **작업 GPT**를 열면 맵·캐릭터·대사·전투 규칙·UI에서 작업 대상을 바꿔 가며 질문할 수 있다. 전송 시점의 선택 대상과 관련 수치가 질문에 포함된다. 화면·메뉴 변경은 미리보기에서 **변경안을 초안에 적용**한 뒤 평소처럼 저장한다.

같은 소유자 계정의 ChatGPT에서 Dreamwalker Studio를 선택하고 **드림워커 제작 GPT 열어 줘**라고 입력한다. 제작 패널에서 바로 질문하거나 **이 대화 연결**을 눌러 웹 편집기의 **작업 GPT**와 연결한다. 사용 방식을 **내 ChatGPT 대화**로 선택하면 편집기에서 보내는 질문이 연결된 대화에서 처리되고 답변이 편집기에 표시된다. 이 방식은 연결된 제작 패널이 동작하는 동안 사용할 수 있다. 태블릿에서 앱이 백그라운드 탭을 멈추면 분할 화면으로 두 창을 열 수 있다. 연결은 두 시간 후 끝나며 양쪽에서 언제든 해제할 수 있다.

## Claude와 제작하기

편집기 위쪽의 **Claude**에서 공유 프로젝트 연결 키를 발급할 수 있다. Claude에서 현재 게임을 읽고 변경을 미리 본 뒤 공유 버전으로 저장한다. **저장 전 초안을 Claude와 주고받기**에서는 선택한 항목과 작업 요청을 복사하고, Claude의 JSON 답변을 검토해 기기 초안에 적용한다. **Claude Code로 스튜디오 개조**에는 제작 도구 자체를 수정할 때 사용할 저장소와 요청 문구가 있다. [연결과 사용 방법](CLAUDE_CODE.md)
